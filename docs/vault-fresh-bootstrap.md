# Trusted fresh Vault bootstrap and archived artifact authentication

`Vault.createBootstrap` persists an exact revision-zero State issued by a validated `WorkspaceActivationHost` publication. This is a constructor-only trusted root capability. It does not accept caller-selected RPC State, reproduce historical credentials, or make an existing restored archive runnable. Ordinary `Vault.create`, `Vault.open`, recovery and snapshot-only custody APIs retain their existing interfaces.

The options extend normal Vault directory/storage/keychain/writer capabilities with `passphrase`, `state`, `expectedStateDigest`, `expectedWorkspaceId`, `expectedOwnerId`, and explicit `VaultBootstrapBudgets`: `maxStateBytes`, `maxJsonDepth`, `maxJsonNodes`, and `maxRecords`. Root must supply independently reviewed pins from the validated activation publication and separately establish that the workspace/owner/session are fresh and distinct from historical authority. The Vault constructor does not derive freshness from a `demo` label or independently validate business projection semantics.

Validation finishes before the first asynchronous filesystem operation. The complete State must be lossless acyclic JSON with ordinary data fields, schema version one, revision zero, exact synthetic workspace identity, one exact pinned active unrestricted owner, and a fresh local policy: no send, autonomy or sharing, bounded retention, and explicit distinct named source grants without `*`. The historical runtime stores `receipts`, `answers`, `decisions`, `actions`, `jobs`, `learning`, `plugins`, `modelReceipts`, `activity`, `conversations`, `routes`, `sessions`, `unsupported`, and `schedules` must be empty. The already validated projected business stores and ontology retain their exact data and nested object insertion order. Undefined values, nonfinite numbers, negative zero, accessors, hidden/symbol fields, sparse or extended arrays, custom prototypes, cycles and unsupported types refuse instead of being silently normalized.

The State digest is the existing order-sensitive `hash(state)`. Bounded serialization preserves its original key order, and the constructor freezes the validated JSON copy before awaiting storage. State wire bytes are limited to at most the existing 32 MiB Vault plaintext cap; depth is limited to at most 256. The caller's lower explicit budgets govern State bytes, depth, nodes and the complete count of top-level store records including the new owner.

The target directory must be explicitly empty and target authority absent. A fresh random Vault identity, 256-bit encryption key, passphrase wrapper/salt and independent recovery wrapper/code are created. The exact pinned State is encrypted and committed at revision zero without a post-create update. Supplied writer admission runs around the actual create-only commit and exact authenticated readback, with one publication callback and synchronous admission assertions. Completed commits whose acknowledgement was lost are resolved through exact authority/readback; promise rejection alone does not imply publication failed. Changed or unresolved authority is never adopted or overwritten.

The return value is the normal `{ vault, recoveryCode }`. No raw encryption key is returned. Existing explicit trusted keychain hooks retain their usual custody semantics. Failed creation closes storage, releases its writer lock, clears key buffers and removes only its own exact committed authority when safe. Existing target work is not touched. Closing and opening the new Vault preserves the independently pinned workspace/owner and revision-zero State.

`vault.authenticateArchivedArtifacts({ sourceVaultId, artifacts }, budget)` authenticates a nonempty exact supplied list of `{ ref, bytes }` entries under `Vault.snapshot`. It requires the current unlocked source Vault identity, the existing explicit encrypted-custody entry/total/count budgets, ordinary complete input fields, typed artifact purposes/IDs, exact `diskBytes` and `valueDigest`, valid UTF-8 and authenticated AES-GCM ciphertext. A fixed two-object-level, nine-field envelope scan refuses duplicate or undeclared JSON fields while preserving legitimate original whitespace and insertion order. Duplicate identities and filesystem case aliases, missing/inconsistent refs, mismatched source Vaults, tampering, and exceeded budgets refuse. It returns authenticated `PrivateArtifactRef & { value }` entries; it exports neither raw keys nor ciphertext and never mounts archived authority.

The helper does not require the original artifact files. Root can authenticate retained archive material after its exact original files have been safely removed through `Vault.removeArtifact` with expected digests. Independent archive inventory/source pins and the expected set of material refs remain root responsibilities; the helper authenticates every supplied entry rather than asserting that a caller-selected subset is a complete workspace. It supplies the bridge's cryptographic material check without same-revision inference or dependence on mutable current files.

Focused tests use actual experimental-file encryption beneath canonical `realpath(tmpdir())`, validated on Windows as `C:` before writing, and controlled prefix/parent checks before cleanup. Fresh persistence is separately qualified from whole activation: these methods alone establish neither Engine/RPC joining, current source/candidate/target exclusion, durable activation journal admission, business projection safety, native storage qualification, nor release readiness. No live-user workspace, provider, model, GUI, native database, downloader, network or paid action is involved.

## Integration rules

1. Receive an explicit committed SHA and producer-local path/bundle or authorized remote ref from each lane. Do not read or import uncommitted lane work.
2. Keep the original recovered checkout intact. The integration worktree has the exact remote baseline ancestry; original recovered history remains separately retained.
3. Give each lane one owner for each shared module. Submit narrow Engine/RPC changes for integration and review before overlapping implementations diverge.
4. Use bounded targeted checks after each meaningful merge. Serialize expensive database/native/full-suite work on the laptop; independent source editing can run in parallel.
5. Update the ledger against actual integrated code and exact evidence. Separate implemented/partial/missing/unassessed from verification state and external qualification.
6. A source test count or fixture run does not establish complete end-to-end acceptance. Keep dedicated security review blocked/unverified and record all remaining platform/vendor/legal gates.
7. Read current remote main before publication and preserve any new work. Never force-push or silently overwrite a different tree.

Hardware capacity queries were access-denied in this restricted executor; RAM and CPU capacity are unverified. Serialize heavy full-suite/native/database checks on the laptop. Bounded targeted checks and independent source editing may continue in parallel. Do not change system permissions or retry the denied hardware queries to obtain capacity information.

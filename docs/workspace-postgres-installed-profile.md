# Installed PostgreSQL transfer profile

`InstalledPostgresWorkspaceProfile` composes the actual PostgreSQL storage,
encrypted backup, original-material readers and activation protocols. It is a
trusted constructor capability for an explicitly approved synthetic workspace.
It is never accepted from an RPC payload, archive, route or retained State.

The source and independently opened journal Vault must be canonical immediate
children of the application directory. The journal adapter must be the exact
instance installed in that Vault. Source admission transfers a fresh owned
adapter, and B retains that same instance through the Vault queue and native
lease. Install every stable target adapter before source capture.
Public semantic export takes that same native source lease inside the existing
Vault snapshot and retains it through initial capture, ciphertext publication
and the final local owner, readiness and file guards.

Each target
slot is the ordinary `hash(<application>/<target>/live/main)` slot, including
the JSON string encoding used by `contracts.hash`.

This profile requires distinct source, journal and target databases, checked
against actual native storage identities. Same-database composition refuses
with `POSTGRES_WORKSPACE_DATABASE_SCOPE`. A separate-database acceptance run
does not qualify same-database capture/publication or arbitrary SQL relations.

B's complete backup capture retains its full SQL/filesystem inventory checks.
Activation uses B's held source plus exact original-material, current owner,
epoch/access/readiness, complete source ciphertext and source/filesystem
fences. Journal/control/target transitions are independently authenticated by
their issuing protocols. They are not exemptions from the backup's final
capture comparison. `fullWorkspacePortable` remains false: wider measured
namespaces and native database/control recovery need separate qualification.

The bootstrap uses a newly generated Vault/key/recovery wrapper and a separately
supplied target passphrase. Historical sessions, provider routes, jobs and owner
authority are not installed. C publishes authenticated filesystem evidence
before A's SQL publication, once. Unknown acknowledgements retain evidence and
require inspection; the profile neither retries publication nor adopts an
existing directory or foreign native authority.

Prepared inspection authenticates the original encrypted custody envelope.
Committed inspection authenticates the actual current native envelope under
the held target lease, preserving sealed business/owner/provider/session
authority while allowing fresh local receipts. `Vault.inspectPostgresSnapshot`
uses existing cryptography without opening a second writer, returning a key or
transferring storage ownership. Native exclusion and ciphertext equality are
checked before and after authentication.

A trusted committed launch holds source admission before the exact owned target
adapter through Vault open, Engine attachment and final publication readback.
Nested target inspection selects that same adapter. Resource closure requested
by invalid credentials or failed attachment is deferred until the native lease
exits; it never changes durable cleanup/publication decisions. Mismatched owned
factory slots are refused and their newly acquired adapters are closed.

Ordinary PostgreSQL Engine admission checks native authority before credentials
or backup intake. Reserved/prepared targets therefore refuse create/open/
recover/restore with `POSTGRES_TARGET_NOT_COMMITTED` before decryption.
The launched sealed profile explicitly refuses target credential recovery with
`ACTIVATION_RECOVERY_PROFILE_REQUIRED`: changing wrappers needs a separately
reviewed current-credential capability. Wider recovery is not certified by this
receipt/reopen profile. Creating/restoring into an occupied committed target
also retains the ordinary Vault refusal.

Injected protocol and cryptographic tests do not establish native qualification.
Only an exact frozen source pin and actual public native transfer, competing
writer/refusal and reopen evidence can support that bounded milestone. This
profile makes no security-audit, installer, GUI, vendor or full-product claim.

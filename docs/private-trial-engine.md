# Private trials: joined local source flow

Engine exposes `trials.savedQuestions`, `trials.create`, `trials.evaluate`, `trials.get`, `trials.receiptContext`, `trials.list`, `trials.discard`, `trials.impact` and `trials.promote`. The strict desktop IPC allowlist includes these exact methods. Public results include paired receipts, exact differences and measured custody costs, never the complete fork States or raw source inputs. Promotion requires the untainted desktop and acknowledgement of the exact current dependency/restatement digest.

Vault encrypts each managed artifact with AES-GCM under a domain-separated key derived inside the existing workspace key hierarchy. Keys are not returned. Opaque purpose-specific file identities, authenticated payload digests, create-only/CAS writes and writer admission bind custody. Forks, evaluations and independent issuance bindings persist through reopening. Discard first seals a revocation tombstone, then deletes only its exact fork/evaluation identities. A retained tombstone and failed cleanup are reported separately; this is logical discard, not a claim of forensic erasure.

New source imports retain the exact original input and full resolved recipe inside encrypted State. Import responses and source lists omit these bodies. Older hash-only imports refuse recipe replay; managed capture remapping still requires a complete qualified custody resolver. No recipe is inferred from a hash. Failed readiness and semantic gates remain refusals.

Promotion rechecks the exact proposal against the draft within the same Vault update that publishes it. Definitions preserve the reviewed compiled hash/metadata; the audit records the later operational activation time separately. Precedence rules publish at actual host time. Complete recipe replacements authenticate the latest full producer generation and preserve the new source input/recipe/row lineage. Incremental fragments cannot masquerade as a complete generation. All old facts and historical receipts remain retained. `supersededAt` controls current versus earlier knowledge-cut selection. Current dependent answers become stale. Retrospective publication appends explicitly labelled restated evidence, preserves original requests/knowledge cuts and leaves original receipt objects untouched; production restatements still use the configured database verifier.

The dependency plan conservatively includes every persisted output, lists rebuild requests and blocks unresolved active jobs, actions or schedules. Native SQL, live vendor qualification and external artifacts are not inferred from these local source tests.

`platform/tests/private-trial-public-flow.test.ts` exercises real loopback HTTP, source admission, three saved calculations, encrypted file custody, reopening, measured discard, exact-impact atomic definition publication, successive recipe generations, historical readback and retrospective evidence. `producer-replacement.test.ts` separately proves complete physical relations `2 -> 1 -> justified empty -> reinstated`, including stale/racing/partial refusal, other producers and original historical receipts. Recipe status reclassification and a physical relation with no outputs are distinct pieces of evidence.

These are synthetic experimental source checks. Renderer side-by-side journeys, installed native/phone journeys, current joined PostgreSQL/DuckDB qualification, shared/team trials and independent release acceptance remain unverified. Dedicated security review remains blocked and is not replaced by ordinary feature correctness tests.

Managed source deletion/retention can remove complete forks containing unrelated forgotten source bytes while some restated receipts survive. A durable hash/ID-only context revocation is recorded before that purge; surviving receipt objects and anchors remain unchanged. Their context endpoint explicitly refuses `RESTATEMENT_CUSTODY_REVOKED`, rather than silently claim the paired interpretation remains available. Unexpected missing custody is separately `RESTATEMENT_CUSTODY_UNAVAILABLE`. These refusals also survive reopening.

Historical restated receipts carry an issued fork/version/publication anchor before database verification. `trials.receiptContext` resolves their paired original/remapped rows through authenticated retained custody and current receipt permissions. Ineligible unpinned or other-member rebuild requests refuse during impact preparation, before any publication reservation.

The existing v1 snapshot-only backup/export cannot include new managed artifact files. It now refuses with `ARTIFACT_BACKUP_REQUIRED` while that custody exists, rather than silently produce an incomplete backup. Complete archive backup remains an open integration requirement. Existing source/profile/workspace deletion flows purge managed whole-workspace artifact copies together with their other managed copies. This is bounded logical cleanup, not forensic erasure.

# PostgreSQL encrypted workspace backup custody

`workspace-backup-postgres.ts` supplies `WorkspaceBackupV2HostPorts` for an actual PostgreSQL Vault. It calls the existing `workspace-backup-v2.ts` codec rather than defining a new archive algorithm. The supported archive contains the reconstructed, authenticated adapter-issued encrypted authority and every original typed private-artifact envelope, including terminal records, reservations, tombstones and prior backup controls. Original physical JSONB serialization is not claimed. Decrypted State is not sorted or rewritten.

Root constructs `createWorkspaceBackupV2PostgresPorts` with the unlocked `vault`, its exact installed `adapter`, `postgres: WorkspacePostgresCustody` bound to that same adapter, canonical direct-parent `applicationDirectory`, six codec `budgets`, positive `{maxFiles,maxBytes,maxDepth}` `filesystemBudgets`, `externalKeyRequirements`, `assertCompleteOwner(context,historicalState)` and held `withCompleteOwner(context,historicalState,work(assertCurrent))`. Paths, credentials, pools, callbacks and adapters are never public payload fields. Operator credential wrappers must have an explicit requirement; an installed keychain additionally needs its own requirement.

The host acquires the Vault snapshot queue before the native advisory/row lease. Nested storage-identity reads use that same retained transaction. Capture independently compares the leased slot incarnation, Vault ID, revision and encrypted envelope digest against the Vault-authenticated envelope. It rechecks owner, epoch, source access and configured consumer readiness before, during and after awaited custody operations. The source pin explicitly retains the actual storage and slot identities, including `creationId`, inside the authenticated `postgres / database/source-slot` requirement with format `chausar.backup-postgres-source.v1`. These identities and complete namespace witnesses also bind `enumerationId`. Recreated slots, storage generations and changed source revisions refuse historical archive admission.

Complete capture enumerates actual user SQL schemas, relations, routines and wider objects through the transaction-bound client. Supported ordinary and partitioned tables receive aggregate bounded row counts, actual physical SQL byte measurements, complete sorted SHA-256 row fingerprints, schema/permission witnesses, column definitions, defaults, constraints, indexes and policies. Relation SHARE locks remain held through the complete source-capture callback and its final assertion. Five-second statement/lock timeouts refuse blocked work. `row_security = off` fails closed when a query would omit policy-filtered rows. User routines, standalone types/collations, user triggers, foreign servers, large objects, extensions beyond builtin plpgsql, views, materialized views, sequences and foreign tables require another reviewed recovery profile and currently refuse. Adding or changing catalog metadata is rechecked; this is not cross-process DDL/crash qualification.

All SQL namespaces remain explicitly outside the State archive. This includes wider rows in `public.chausar_vault_authority`, storage-generation and publication-custody tables, and enterprise `chausar_core`/`chausar_source` tables. They are not silently counted as exported business State. Physical SQL bytes use the explicit inspection byte budget, and row enumeration uses an aggregate record budget; exceeding either refuses rather than truncates.

Filesystem capture independently hashes safe regular files and compares each private ciphertext's measured bytes/hash/ref to complete Vault authentication. Known wider workspace/application namespaces are measured and classified outside the archive or transient process custody. `outsideApplicationNamespaces: [{name,requirement}]` is root authorization to hash and measure named siblings, such as the dedicated journal or activation directories, without decrypting or admitting them. Unknown siblings refuse. Declared populated siblings never receive invented zero measurements. Only exact controls newly written by this operation are allowed as source-inventory changes.

Each backup uses separate encrypted archive, independent pin and issuance-binding artifacts, with create-only IDs, durable preparing/committed/discarded phases and exact compare-and-swap ownership. Rejected issuance removes only its original payload and retains a single-use tombstone. Completed encrypted writes with lost acknowledgements are resolved by exact authenticated readback. `custodyMeasurement` reports archive, pin, binding, total retained and removed ciphertext bytes; generic summaries retain the existing `encrypted-local-host` enum. Diagnostics explicitly distinguish `storageKind:'postgres'` and `authorityKind:'adapter-issued-envelope'`. That enum is not native PostgreSQL qualification.

Inert restore allocates a fresh physical directory and durable source-encrypted reservation, publishes one fully authenticated `backup.inert.json` container without overwrite, and retains both directory and container inode generations. Every direct reader verifies the full receipt shape, source pin, entries and bytes. Rollback and failure cleanup compare exact original creation/digests, directory generation, container generation and sole-entry custody; a byte-identical replacement is retained with a cleanup-required refusal. The container never installs runnable authority or historical process/session credentials. Its filesystem target is distinct from the later activation target and PostgreSQL slot. SQL absent-slot proof, publication, lost-ack inspection and exact SQL rollback belong to the storage/activation lanes; this host never deletes a SQL authority slot.

Coordinator joins can use `withHeldSource`, `inspectHeldNamespaces`, `withArchiveReader`, `withInertReader`, `restoredIdentity`, `targetPath`, `diagnostics` and `custodyMeasurement`. `inspectHeldNamespaces` includes `{postgres:{storage,authority,catalog},physical,directories,files,namespaces}`. Constructor-only activation inspection retains native source-slot exclusion and measured wider witnesses, without relation SHARE locks that would block the separate target publication transaction in the same database. The coordinator must hold its actual journal/target/readiness custody and authenticate cross-store phases. Prepared target exclusion, fresh Engine admission and receipt recalculation remain coordinator/activation work.

`fullWorkspacePortable` remains false. Wider filesystem/SQL payload recovery, external credentials, full public Engine/HTTP transfer, actual PostgreSQL writer exclusion, fresh billed/received/earned receipts after reopen, crash/power-loss and uncertain cross-store publication remain joined qualification gates. Focused tests use authored SQL protocol responses with real Vault encryption and safe C-only filesystem custody; they are not native server evidence. PGlite remains failed and nondefault.

The native gate must include a direct SQL updater that acquires a table write lock while waiting on the source row, since the later SHARE-lock upgrade can cause a bounded timeout/deadlock refusal. Successful advisory-lock writer exclusion in a protocol fixture does not qualify that contention timing. Catalog creation after final inspection, OS crash/power loss, relation permissions/RLS and Windows inode boundaries also require actual joined native evidence.

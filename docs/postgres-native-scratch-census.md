# Native fixture scratch census

The PostgreSQL transfer fixture's scratch census is resource accounting, separate from production source, target, catalogue and authority admission. It counts every directory entry and every regular-file pathname under the exact owned C: run root. Hidden files, stable artifacts and hardlinked regular paths are not filtered or deduplicated. Symlinks, junctions, unsupported file types, escaping names, replacement roots and entry/byte overflow refuse.

Startup and live monitoring permit at most three COMPLETE census attempts within one shared five-second traversal/retry budget. A descendant disappearance (`ENOENT` during lstat, readdir or canonical directory inspection) discards the entire partial traversal. The next attempt starts with zero bytes/entries and revalidates the original canonical run/permitted-root physical generations. A missing root, another filesystem error, unsafe path/type/link, changed physical custody or exceeded budget remains fatal. A successful restarted scan is a complete current scan; missing entries are never silently skipped inside an accepted partial count.

Both stopped-state censuses remain strict single attempts within their existing ten-second cleanup bounds. `finalScratchBeforeSaveChecked` and `finalScratchAfterSaveChecked` record their separate results; `finalScratchChecked` requires both. A later census failure is persisted as a failure even when PostgreSQL is independently confirmed stopped. The final successful evidence update must not grow beyond the lifecycle bytes included in the just-completed cap check. Failure evidence may record the refusal but cannot qualify cleanup as successful.

Diagnostics retain only a closed phase, attempt, operation, allowlisted code, namespace and exact bounded relative pathname with a digest. They include no absolute path, error message/stack, SQL, ciphertext or credentials. Up to 32 events are retained with an explicit dropped-event count. Observer errors cannot affect census results.

The monotonic deadline is checked before and after filesystem awaits and is shared across retries. It does not interrupt an operating-system filesystem operation; supervisor and cleanup bounds remain the hard wall-clock backstop. HTTP review retains its original 30-second deadline. Native profiling/activation qualification must use a fresh frozen source and the independently corrected comparison fixture; offline filesystem tests do not establish either.

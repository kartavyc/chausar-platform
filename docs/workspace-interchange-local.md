# Local workspace interchange custody

`createWorkspaceInterchangeLocalPorts({ vault, applicationDirectory, assertCompleteOwner, qualification })` returns a trusted local adapter with `.ports` for `WorkspaceInterchangeHost`, `.targetPath(targetId)`, `.diagnostics()` and `.custodyMeasurement(recordId)`. None is a renderer key or arbitrary filesystem port. Root still owns Engine/HTTP/IPC wiring and activation.

The source is one direct managed workspace below the canonical application folder. `Vault.snapshot()` holds the source authority queue through actual filesystem enumeration and the host operation. Every source assertion rechecks current unrestricted desktop ownership, source permissions, the required root consumer-readiness callback, complete State and retained business bytes. Capture/generation pins are deterministic and survive a normal close/reopen when the bytes and authority remain unchanged.

The local profile retains all 26 State stores, exact legacy originals/full recipes from verified `retainedInput`, connector full recipes/pages and existing bridge provenance, inline dictionary/plugin bytes, owned authenticated private trials, and real regular files in the declared `reports`, `plugin-assets`, `research-evidence`, `conversation-files` and `sync-evidence` namespaces. Source-owned managed `backups` and `exports` are opaque original bytes. Other-workspace backup/export filenames are classified without opening their contents. Missing legacy bodies, missing private issuance payloads, altered raw/provenance pins, unclassified entries and links refuse the capture. Quarantined/unqualified connector states remain unchanged; retaining their evidence does not qualify them.

Private forks require their exact owned issuance binding and current complete-read admission for both retained historical views. Revoked sources cannot reappear through a fork after their live facts have been removed. Copying another member's private custody is refused. Discarded private issuance tombstones may remain after their payloads have been deleted; unresolved revoked payload cleanup refuses completeness.

Archive content and its independently issued inventory pin are separate ciphertexts under Vault's workspace-derived artifact hierarchy. A third authenticated commit binding references both exact ciphertext digests and a unique issuance instance. It is the publication marker. Actual file sizes, the binding footprint, operation duration and discard bytes are measured. Reads authenticate all three and survive restart. Create-only IDs cannot overwrite existing, orphaned or discarded committed records. Discard first changes the binding to a durable tombstone, then CAS-removes only the bound archive/pin. Committed record IDs are single-use, preventing delayed rollback from deleting a same-ID replacement.

Write failures after a real filesystem publication are resolved by authenticating the exact actual owned payloads/marker before cleanup. Archive/pin failures without a returned reference, final-binding acknowledgement failure, and target-reservation acknowledgement failure have dedicated real-Vault regressions. Unresolved cleanup returns a precise custody error; orphan files are never silently adopted. This is logical publication and restart evidence, not power-loss certification.

Targets are new physical empty directories with independently allocated workspace IDs and immutable physical/generation reservations. Existing unrelated directories are refused. Target reservation ciphertext and process locks are outside the target directory. Every held inspection checks actual entries, all 26 zero store counts, all nine zero artifact-category counts, zero authority and current access. Candidate review fails if even one unexpected target file appears. Discard does not erase a target reservation or unrelated target work. No historical sessions, jobs, actions, plugins or routes are activated by this module.

Custody always takes the Vault authority queue before its record/target process locks. Within a held source snapshot it reuses the artifact scope. This prevents reverse queue/lock ordering between export and review. Locks use the existing bounded local process-lock implementation; no new authentication or persistent access is created.

The codec's 64 MiB business payload/file and 4,096 artifact bounds apply incrementally before retained buffer allocation. Private ciphertext metadata is checked before Vault inventory decryption against the remaining conservative budget. The separate administrative ciphertext namespace is bounded to 256 MiB for local inspection. These are bounded-operation refusals, not automatic source truncation. A focused regression uses two individually legal 40 MiB and 25 MiB files to prove aggregate refusal.

## Explicit scope and remaining gaps

Diagnostics always report `fullWorkspacePortabilityQualified: false` and `desktop-business-payload-with-control-exclusions`. The decoded State substitutes for the original authority wrapper/storage representation; Vault wrapping keys and live writer locks are not portable business artifacts. This adapter's own archive/pin/commit/tombstone/target-reservation ciphertext and external process controls are administrative control outside the portable business payload. The exclusion prevents recursive self-containing exports, but does **not** qualify full portability of all managed interchange archives. Independent acceptance must reconcile that full-scope requirement.

Opaque encrypted backups/exports retain exact original bytes while still depending on original external key custody; this module does not release or migrate those keys. External sync stores, configured semantic dossier bytes, process-only pending reads, enterprise PostgreSQL/Temporal namespaces and arbitrary external customer files are outside this local profile and remain unqualified. The root must supply current consumer readiness and refuse unresolved source custody; a no-op readiness callback is allowed only in explicitly labelled synthetic test fixtures.

There is no plaintext-output port, public Engine/HTTP/IPC integration, activation, native database qualification, GUI, external model call, vendor qualification, or real user vault migration in this slice. The focused tests use actual experimental-file Vault storage and canonical C-drive temporary fixture directories, with checked owned cleanup. Root must prove the public synthetic flow separately.

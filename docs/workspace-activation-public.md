# Public synthetic workspace activation

The Engine composes the complete encrypted v2 archive, independent semantic export, inert restored copy and durable activation journal into a separately reviewed synthetic business projection. Publication initializes a new experimental-file Vault at revision zero with a new workspace identity, owner and encryption wrappers. The trusted host can then start a separate Engine and loopback HTTP server for that exact committed target.

The source workspace must appear in the constructor's `WorkspaceActivationPolicy.approvedSyntheticWorkspaceIds`; every activated business source must appear in `allowedSyntheticSourceIds`. A demo flag, caller label or self-consistent hash does not provide that approval. The constructor also requires a distinct actual encrypted `journalVault` and an explicit `targetPassphrase(authority)` capability. RPC payloads cannot install any of these capabilities, filesystem paths, callbacks or credentials.

The supported order is:

1. Commit `workspace.interchange.export {destinationId, confirmed: true}` for the complete reviewed business material.
2. Create and read `workspace.backup.v2.create {destinationId, confirmed: true}` / `workspace.backup.v2.read {backupId}`. Its original encrypted capture must contain the exact independent export archive, pin and committed binding envelopes.
3. Create `workspace.backup.v2.restoreInert {backupId, targetId, reviewedDigest, confirmed: true}` and retain its actual `creationId`. This closed copy remains inert.
4. Reserve a distinct new empty physical target with `workspace.activation.target.create {targetId, confirmed: true}`. `workspace.activation.target.get {targetId}` reauthenticates its current empty reservation.
5. Prepare `workspace.backup.activation.prepare {backupId, materialId, inertTargetId, inertCreationId, candidateId, targetId, reviewedArchiveDigest, confirmed: true}`. `workspace.backup.activation.inspect {candidateId}` returns only the authenticated review metadata before activation.
6. Review `workspace.activation.review {candidateId, reviewedDigest}` and acknowledge its separate `projectionDigest`.
7. Execute `workspace.activation.execute {candidateId, reviewedDigest, projectionDigest, activationId, confirmed: true}` once. Use `workspace.activation.get {activationId}` for explicit committed readback and restart inspection.

The bridge review acknowledges the original archive and derived inert candidate. The activation review acknowledges which business stores become live and which historical control stores remain inert. Their digests serve different reviews. Replaced custody, changed review digests, an existing target, unapproved sources and replay refuse. A possibly committed publication remains retained for explicit inspection; the public flow does not retry or overwrite it automatically.

Activation readback preserves the immutable activation IDs, authority, projection and evidence pins. Its `ciphertextBytes` measures the actual current encrypted target files, including the evolving live authority. New retained receipts and answers increase that byte count without changing the original bootstrap or its immutable summary fields. The public test compares every immutable field and independently totals the actual bootstrap, evidence and live authority files after target close.

`Engine.activatedWorkspaceEngine(context, activationId)` is a trusted host factory. It authenticates the committed target and returns a fresh Engine with its workspace and owner pins. It carries forward no source gateway, provider credentials, connector configuration, sync configuration, job runner or historical sessions. The host calls `createLocalServer(newEngine)` to obtain a new transport token, then performs ordinary `workspace.open` with the separately supplied fresh target passphrase. Public activation routes return metadata; they do not return an Engine, paths, retained archive bodies, decrypted private evidence, keys or passphrases. Close the target Vault before source activation readback or another launch inspection because experimental-file Vault writers are exclusive.

The live projection retains the exact published ontology, facts, supported legacy imports and original retained inputs, business conflicts, merges, tombstones and reviewed source precedence. The target has one freshly allocated unrestricted owner and a fresh policy: `send: 'nothing'`, `autonomy: false`, `sharing: false`, explicitly approved source IDs and the configured retention period. Historical members, policies, sessions, routes, receipts, answers, jobs, actions, schedules, plugins, model records and private artifacts remain encrypted inert evidence. They become no target authority and trigger no automatic execution. Original v2 ciphertexts, wrappers and namespace dispositions remain preserved; `fullWorkspacePortable` stays false. Managed connector history requires its separate fresh profile and consumer gates and refuses this synthetic activation profile.

`platform/tests/workspace-activation-public.test.ts` exercises the complete flow through actual loopback HTTP and actual synthetic source, journal and target experimental-file Vaults in newly allocated C-drive temporary storage. It creates the ten retained CSV rows with actual `sources.import` and the retail starter pack, then records the source baseline through `calculation.run`. The fresh target receives actual `conversation.ask` requests for “What was billed?”, “What was received?” and “What was earned?”, and `receipts.get` reauthenticates each returned receipt. The September goldens are billed **300000**, received **260000** and earned **250000** minor units. Three new target receipts match the original business semantics under the fresh owner; closing and reopening all custody produces three further receipts with distinct IDs and the same semantics. The checks also cover exact original ciphertext inclusion, encrypted private history retention, metadata-only responses, constructor source scope, explicit confirmation, stale reviews, new wrappers, empty runtime stores, old HTTP/session-token refusal and durable replay refusal. The test performs no inference request or automatic job dispatch.

Run the bounded public check with the already installed runtime:

```powershell
node --test --test-concurrency=1 --test-reporter=tap platform/tests/workspace-activation-public.test.ts
```

It acquires no dependencies, reads no user vaults, sends no external messages and writes no D-drive data.

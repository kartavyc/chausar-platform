## Current release and fresh-owner behavior

The codec remains a structural/checksum tool and provides no source provenance or access authority. Installed Engine complete-owner admission now invokes `EngineScenarioService.assertInterchangeRead` and, when populated lesson history exists, `LessonService.assertInterchangeRead`. These are trusted host methods, not RPC endpoints. They compare exact current encrypted custody, then use actual current scenario reopen/graph and lesson full-history checks. They cover private owner and epoch, source/branch access, every retained revision and receipt, episodes, candidate/lifecycle references, target/evaluation evidence and current retention. A trusted scenario readiness generation brackets all scenario records; the returned synchronous current-fence assertion also runs after lesson admission. This prevents a later scenario or lesson resolver from withdrawing an earlier scenario's readiness within the same release. Populated scenario copying requires the existing installed `discoveryAuthorityRevision` capability, including current connector readiness generations; a dynamic connector configuration lacking `readinessRevision` remains unsupported for complete copying even if an individual ordinary reopen succeeds. Unavailable lesson authority refuses populated history. Empty or absent namespaces require no invented authority. Existing source/evaluation resolvers determine readiness; unsupported evidence has no generic fact-access fallback. Existing fenced export/review/custody rechecks continue to invoke admission through publication and readback.

Fresh-owner activation retains both namespaces in the exact original candidate/archive inside encrypted inert evidence and declares each present namespace in its inert-store review. It does not copy them into fresh active `State`, change their IDs, rewrite ownership, reseal digests or revive an approved lesson. The new workspace therefore starts without scenario or lesson runtime authority. Historical inspection and ordinary same-owner encrypted reopen are different journeys: ordinary reopen retains its original exact records and existing current release checks.

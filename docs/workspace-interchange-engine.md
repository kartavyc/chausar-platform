# Joined encrypted workspace transfer

Engine exposes `workspace.interchange.export`, `workspace.interchange.prepare`, `workspace.interchange.review`, `workspace.interchange.discard` and `workspace.interchange.diagnostics` through loopback HTTP and the strict desktop IPC contract. Destinations, candidates and targets are explicit opaque managed identities; public inputs cannot select arbitrary paths, supply custody ports or release wrapping keys. Public summaries report the exact package/review pins, complete store/category counts and measured encrypted archive/pin bytes. The local diagnostic describes its last capture and explicitly reports full portability as unqualified.

The actual local adapter runs inside the open Vault snapshot queue. The root repeats current unrestricted desktop ownership, every retained historical source/row permission and the installed managed semantic/readiness gate. Configured device sync refuses with `INTERCHANGE_EXTERNAL_CUSTODY_REQUIRED` until its external namespaces have independently enumerated custody. The actual source enumerator refuses missing originals/recipes, unknown files and changed source or target generations. Candidates remain encrypted and inert across reopening. A normal reopen with no interrupted work preserves the authority revision; real interrupted actions/jobs still perform recovery and invalidate older source pins.

Review does not initialize or attach the target. No old session, route, plugin, approval, job, lease or schedule becomes authority. Discard removes only the exact owned archive/pin payloads; retained issuance tombstones and empty target reservations are reported administrative evidence. There is no public plaintext or activation endpoint in this join.

`workspace-interchange-public-flow.test.ts` exercises the actual HTTP/Vault source flow separately from the codec, asynchronous host fixtures and local custody tests. All fixtures are synthetic experimental-file workspaces with no provider dispatch. Full archive-inclusive backup/portability, controlled activation with three recalculations, renderer journeys, real database/native qualification, remote/team transfer and real-user migration remain open acceptance work. These requirements have not been removed from full scope. Dedicated release security review remains blocked/unverified.

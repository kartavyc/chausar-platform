# Bounded bilingual core operation discovery

The current-source check at `f865de1abeef7c2646d564f075f6e34162c7c83e` reproduced all nine original Hindi refusals through `conversation.ask` without a model route. The typed calculation fixtures passed because their operations had already been selected by the fixture author. These are separate observations.

The source architecture requires model interpretation to select typed operations while deterministic code performs arithmetic (`docs/specs/CHAUSAR-ARCHITECTURE.md`, the final plan's language-to-operation mapping). It also explicitly requires a Hindi/English wordlist (`docs/specs/CHAUSAR-LIVE-BUILD-PLAN.md`, line 247) and aliases stored as data bound to definition and calculation identities (`docs/specs/GAP-REGISTER.md`, ONT-32; `docs/specs/CHAUSAR-FINAL-IN-DEPTH-PLAN.md`, identity/versioned-discovery requirements). The existing no-route local calculator supported only English phrases. The selected-model gateway remains the path for broader interpretation.

`platform/runtime/core-operation-aliases.v1.json` supplies a reviewed, versioned wordlist and finite sentence frames for six existing core operations: billed amount, received cash, earned revenue, refunds, net sales and contribution margin. `core-operation-aliases.ts` validates bounds and resolves complete normalized utterances, tolerating Unicode normalization, whitespace, case and terminal punctuation. It never extracts a keyword, period, filter, amount or instruction from a larger question. Invoice-count frames are absent; bare cash-balance phrases do not select received cash. Accounting profit, generic sales, causal questions, mixed questions and negation are outside the wordlist.

An alias is eligible only when the current dictionary's domain pack and currency match an existing starter pack; the current operation has the same identity, type, ordered definition references and parameters; and every contributing definition exactly matches the starter definition's complete semantics. Changed definitions, duplicate relevant definitions or operation identities, and mismatched parameters disable the alias. Net sales and margin bind all their dependencies. Competing eligible aliases return an ambiguous result and the ordinary unsupported response, rather than choosing by order. A successful resolution includes the current dictionary hash and contributing-definition hash; calculation still passes through existing authorization, current publication and receipt checks.

`Calculator.ask` tries this bounded discovery before its existing local English parser. An ineligible alias does not disable that legacy parser: for example, `What was billed?` still selects a published owner-customized billed definition through its previous English grammar. A new Hindi alias or newly added English phrase such as `What were refunds?` cannot inherit changed core semantics. A public regression pins that distinction. Model routing, Engine, Vault, shared IPC, security policy and deterministic arithmetic are unchanged. Unrecognized phrases still follow the existing wanted-question path. This implements a narrow core question-discovery subset: a general recipe-wide wordlist, broader language interpretation and custom-definition aliases remain separate work.

The original nine Hindi questions are preserved verbatim in the benchmark fixture. Six now answer with literal expected minor-unit values and saved public-API receipts. The ambiguous-sales, accounting-profit and causal questions retain exact refusal expectations. English controls also have six answers and three refusals, including the newly recognized whole phrase `What were refunds?`. Public regressions independently phrase all six Hindi and English calculations, verify count/balance/ambiguity/negation refusals, and exercise branch, member, source, receipt and locked-workspace authority. Pure tests cover all six domain packs, changed semantics, competing aliases and bounded pack validation.

All evidence uses authored synthetic CSV fixtures, experimental file storage and the public Engine API. Provider transports fail closed, with zero model dispatches and zero model receipts asserted. These checks establish deterministic source behavior for the finite alias pack. They do not establish general Hindi understanding, live-model quality, native process/storage/client qualification, clean-machine readiness, production readiness, a text-to-SQL comparison, public-release acceptance or the blocked security audit.

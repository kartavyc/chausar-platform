# Reviewed grounded final answers

A completed conversation now has a separate writing stage after local tool execution. The planner chooses registered business and calculation tools; the Engine executes them and saves the current tool turn. **Review final answer** builds a distinct preview containing the retained original objective, admitted claim text, opaque citation references and figure/scope descriptors. Exact amounts, dates, rows and receipt identifiers remain local. Approved samples policy and another exact one-use approval are required. Previewing or reopening does not invoke a model.

The synthesis response supplies natural prose with typed evidence slots. The production validator from module commit `20fb1dee969cf7c66bf48d2b66ae0b273789b5da` enforces bounded JSON, declared aliases, closed citations, useful content from every tool, every figure/scope, mandatory cautions and numeric-text restrictions. The host adapter also applies the numeric-slot rule to written Hindi numbers/currency terms. These deterministic checks do not establish that every free-prose sentence is semantically entailed; broader model qualification remains unverified.

The host renders slots directly from current calculator displays and attributed business claims. It independently reconstructs the materialized text, required warnings and paragraph references. A separately signed final-answer record binds the original tool turn, planner and synthesis model receipts, exact summary/output digests and full selected source/row authority, including zero-row selections. Its saved reader validates both model receipts, all tool children, source access, readiness, retention and exact local rendering without inference or recalculation. Expired, changed, duplicated or revoked bindings withhold the narrative rather than using cached text.

The current renderer places the final paragraphs and warnings above collapsed tool receipts/citations. It uses the strict desktop methods `conversation.synthesis.preview({ id })` and `conversation.synthesis.run({ id, previewId, approvalId })`; callers cannot provide tool bodies, custody, receipts, readiness evidence or model instructions. No automatic second provider call, retry, route fallback or paid fallback is installed. Existing local calculator and tool-only answers remain readable under their existing current-authority rules.

The implementation is source-level progress. Authored synthetic HTTP responses test the actual production codec, Engine/Gateway, encrypted retention and renderer/IPC boundaries. They do not qualify live Luna/account access, commercial sign-in eligibility, Electron GUI, native installers, hosted/enterprise operation or named vendor adapters. The dedicated security review remains blocked and unverified.

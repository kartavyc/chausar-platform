# Grounded business introductions

The reported question, `what is the business about`, previously entered a calculation-only provider schema. Shape disclosure also removed `business` and `about`, leaving `what is`. A model could only return an allowed financial operation or request clarification; it could not release a business description.

`conversation.ask` now recognizes bounded general introductions such as that question, `Describe our business`, and `What does our business do?`. Other questions retain the analytical calculator path. An explicit `purpose: 'business-context'` requires one of those introductions; it cannot reroute a financial or investigative question around calculation gates. This implements the introduction path, not every conversation requirement in the full plan.

Without a selected model route, the introduction remains local and works under `send: nothing`. Current workspace metadata, published dictionary definitions, permitted imported record types, explicit owner statements and clearly labelled draft assumptions are separate evidence classes. A selected dictionary pack does not establish actual industry. Missing industry, products, customers, business model and location remain visible unknowns. Unresolved claims remain disputes. Imported observations do not qualify themselves.

Managed observations use the actual connector readiness service: current installed profiles, source grants, custody, freshness, qualified semantic evidence, capture lineage and retained independent anchors are rechecked. Missing profiles, unpublished domains, stale evidence and changed translations refuse release. Ordinary CSV observations retain `unqualified-observation`; invoking a guard cannot silently upgrade them. A context containing a synthetic managed source keeps its synthetic scope label even in a workspace that is not marked demo.

With a selected model route, the provider returns only bounded generic claim IDs and declared unknown categories. The application renders their current local text and citations. Model prose, invented facts, amounts, URLs, actions and tools are refused. Shape sends a fixed generic introduction intent and category aliases; names, values, record counts, source/citation/object identifiers and the original question remain local. Samples contain at most five explicitly selected claim scalars through `profileSamples: [{ claimId }]`; there is no automatic fact sampling for introductions. A private workspace-name sample requires exact outbound approval even when no facts exist.

Preview binds the exact question, purpose, route, scope, selected samples, output schema and local context digest. Membership, permissions, source content, dictionary/workspace/profile versions, readiness and exact approval are checked before dispatch, in the publication transaction and before release. A provider gets one attempt, without fallback. Explicit incomplete/refusal/error output cannot release an answer. Tests use labelled synthetic transports; no extra native inference was performed.

Every released answer retains a `business-context-receipt` in the existing encrypted conversation collection with source/row/profile lineage. `business.context.receipt({ id })` reauthorizes the current account and context. It is explicitly not a financial calculation receipt. The actual renderer shows separate claims, unknowns, citations and scope, and opens this receipt through the existing strict preload. Source/profile deletion removes dependent retained answers and payloads and triggers managed-copy purge.

Typed descriptions use `business.profile.record`, `business.profile.history` and `business.profile.remove`. Record/remove require an untainted desktop request; owner statements additionally require the existing administrative role. The caller supplies the category, text, origin, source, business date and optional branch/correction reference. No industry or business model is assumed. Financial assertions require the typed financial path. The profile editor and broader conversational recall/investigation interfaces remain separate unfinished product work.

Focused evidence includes paired HTTP import → local introduction → context receipt → exact billed receipt, typed profile removal, exact approved synthetic provider selection, actual preload/worker context-and-calculation roundtrip, current-state races and a qualified synthetic translated connector context. Native GUI/provider acceptance, live vendor qualification, full conversation coverage, enterprise and dedicated security review are not certified by these checks.

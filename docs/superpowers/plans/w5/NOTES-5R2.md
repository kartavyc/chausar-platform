## Working scope and seams

Two owner-priced offers, monthly data entry and backlog project. Source-column mapping is approved before filling. Every new site requires the exact permission/risk acknowledgement. Government portals and marketplace seller dashboards are denied. The owner types credentials directly; agents never receive a password, arbitrary JavaScript, selector or local upload path.

Build pure mapping/readback/deny first, then source-bound desk and journalled form-fill operations, then the real desktop owner browser and trusted worker/main relay, followed by owner UI/fake/Hindi and complete delivery tools. Reuse the existing print-port relay pattern for trusted host composition. A renderer request must never supply an authority-bearing success or approval claim.

The desktop will use a fresh run partition unless the owner explicitly selects a saved sign-in. Typed operations use opaque snapshot target IDs and check current target/form/page/source identity at the physical action. Captured text pages must share one complete page hash. Screenshots and readbacks are private source evidence, erased by Forget and invalidated when the source or page changes.

Filling a field may trigger autosave. Holding only a submit button is insufficient. Renderer-initiated network effects during fill must be blocked; only an exact owner-approved submit may cross the physical gate. Unknown or unsupported auto-save/multiple-effect behavior stays held with a manual path. No retry after a possibly sent write, no success without an actual saved-record identity and field comparison. This network boundary is still pending implementation and qualification.

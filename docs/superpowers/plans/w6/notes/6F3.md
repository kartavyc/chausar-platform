# 6F3 Web search and reading (D32)

## What was built

- **Search: the AI tool's own first.** The driver side already existed from 6B7: `webSearch: 'research'` in the saved AI settings turns on Codex `web_search: 'live'` and Claude Code's WebSearch and WebFetch only for playbooks whose trusted service type is research (`agent-runtime/route.ts`, `settings.ts`). 6F3 adds one rule to it: Claude's WebFetch now follows the fetch policy (no terms-barred site, no LinkedIn or other profile site, no address inside the computer or its network) in `agent-runtime/claude-driver.ts` `toolAllowed`.
- **The owner's own search key** (`web/search.ts`, `web/search-data.ts`, `web/search-types.ts`): Brave Search, Exa or Tavily only (no DuckDuckGo or other scraped engine). `venture.web.search` reads the view; `{ provider, key, consentDigest }` saves the key in protected storage (credential names `search:brave|exa|tavily`, added to `models/credential-contract.cjs`) after a consent that names the provider and what goes to it; `{ provider: null }` removes it. The business file keeps the provider, last four characters, date and consent digest (`VentureRecord.webSearchKey`). Each request goes once through the network guard as Chausar, never retried; results are shaped to address, title and snippet, private and non-http addresses dropped. Every provider is labelled fixture-tested.
- **The key feeds Chausar's own lookups.** `savedWebSearch(deps)` (host-composed search first, else the saved key) now backs a network search's outside pages, Before you write and the network sources card (`network/search.ts`, `research.ts`, `methods.ts`, one line each).
- **Polite reading, in the fetcher the SEO checks already use** (`build/fetch-policy.ts`, extended rather than a second fetcher): one request per site every 3 seconds (`POLITE_GAP_MS`; robots.txt exempt), robots.txt kept an hour, a full stop at a CAPTCHA (`CAPTCHA_STOP`: no retry, no other route, that site left alone for a day; a reCAPTCHA on an ordinary contact form is not a stop, the same widget on a 401/403/429/503 is), and a pause when a site answers 429 (`SITE_PAUSED`, Retry-After capped at an hour). The state belongs to the underlying sender: the real `pinnedSend` is paced by default; injected senders are quiet unless given `usePoliteness`, but all stop at a CAPTCHA. The wait comes out of the request deadline.
- **The reader** (`web/reader.ts`): `readPage` goes through politeFetch + robotsSafe, keeps the main text with Mozilla Readability (run on a clean, well-formed copy made with parse5; scripts, styles, frames, comments and `on*` attributes never reach it), screens the text as untrusted (`enforce`; a page with words aimed at the AI is `PAGE_HELD`), labels it "From a public page, not confirmed", and keeps it 30 minutes in memory (64 pages; the shared cache only for the real network). `crawlSite` reads up to 10 pages of one site, two links deep, own links only, skips refused pages and stops the whole crawl at a CAPTCHA or a 429.
- **JavaScript pages, desktop only:** `web/render-port.ts` (worker side), `app/desktop/web-render.cjs` (hidden sandboxed Electron window, its own in-memory session with Chausar's user agent, no permission, download or popup, no navigation off the site, requests checked for http/https, public addresses by literal and by lookup, and terms-barred hosts; storage cleared after each read), relayed by `engine-harness.cjs` (`host-render`) and `main.cjs` (`render`), composed in `worker.ts` and passed by `host.ts` only on the desktop (`VentureDeps.webRender`). The engine asks it only after robots.txt allowed the page and the site's pace slot came up; a CAPTCHA in the rendered page stops the site too.
- **`venture.web.read { url }`**: shows the owner what the reader keeps from one page (first 4,000 characters). Nothing is stored.
- **UI:** "Web search and reading" inside the closed "More ways to connect" fold (`places/connections/WebSearch.tsx`, text in `text/en/web-people.json`), so nothing is added at rest. Label "Reads".
- **Fake engine:** `engine/fake-web-people.ts`, using the engine's own pure checks and views (`web/search-data.ts`); reads no page (a labelled sample page).
- **Dependency:** `@mozilla/readability` 0.6.0 (Apache-2.0, no dependencies) added to `package.json`. To avoid disturbing the shared `node_modules` while other helpers ran tests, I unpacked the published tarball into `node_modules/@mozilla/readability` instead of running `npm install`; the integrator should run the approved install so the lockfile records it.

## Deviations and why

- **Crawlee is not used; founder decision needed.** Crawlee's HTTP crawlers send generated browser headers and fingerprints by default (got-scraping with header-generator) and carry proxy rotation and session pools, which D32 ("an honest bot name, no proxies") and the hard stop on detection evasion rule out. Its BasicCrawler alone would only give a queue, at the cost of about forty extra packages including the fingerprint generator. `crawlSite` is a small breadth-first crawl on the polite reader instead (10 pages, 2 deep, own site). If the founder still wants Crawlee, BasicCrawler can wrap `readPage` as its request handler without changing behaviour.
- Pacing applies to the real network sender only; tests and an owner site's own API calls are not slowed. A CAPTCHA stops every sender.
- The AI tool's own search needed no driver change beyond the WebFetch policy; Codex's built-in `web_search` cannot be filtered per address by Chausar, so it is not covered by the terms list (it is the tool's own service under D32).
- The owner's search key powers Chausar's own lookups, not the AI tool: adding a search tool to the scoped MCP toolbox would change the pinned eleven tool names while 6F1 edits the same area. Open item below.
- `venture.web.search` reads and writes in one method, like 6F6's `venture.notify.telegram`, and is app-only.

# 6F7 Phone access (D35), tested on this computer's loopback; no real phone yet

## What was built

- **Extends the existing pairing, not a second one.** The owner's local server (`platform/runtime/server.ts createLocalServer`) gains a phone mode (`options.phone`), and the phone uses the existing member sessions (`auth.session`) and the web client's existing in-memory bearer. In phone mode the server:
  - accepts only peers on this computer, its home network (10/8, 172.16/12, 192.168/16) or Tailscale (100.64/10), and only the host names of this computer's own addresses;
  - never accepts the desktop bootstrap token, and serves none of `/api/session`, `/mcp` or `/api/companion/rpc`;
  - gives every request the channel `phone` (`engine.contextForSession(token, 'phone')`), so every app-only method (for example `venture.ai.connect`, `venture.compose.decide` and `fill`, billing, these phone and Telegram settings) is refused exactly as the code already refuses a phone, and the bootstrap-only methods stay refused too;
  - also refuses `auth.*`, `phone.*`, `members.*`, `trust.*` and `workspace.*` except `workspace.status`, so a phone cannot mint sessions or change the workspace;
  - accepts only bearer tokens this listener issued in this run.
  - `stopListening()` closes the listener without shutting down the engine.
- **The pairing link** (`platform/runtime/phone-access.ts createPhoneAccess`): `http://<Wi-Fi or Tailscale address>:<port>/#pair=<43-character one-time code>`. The code is in the fragment (never in a server log), works once, for 10 minutes; ten wrong codes in a row end every open link. `/api/phone/pair` trades it for a member session of the owner, 12 hours unless the owner chooses (1 to 24). Stop revokes every phone session it issued and closes the listener. The listener starts only when the owner makes a link; it binds all interfaces and checks peer and host name on every request.
- **Engine method** `venture.phone.access` (approve, app only; `platform/runtime/venture/notify/phone.ts`): `{}` reads, `{ action: 'link', via?: 'wifi' | 'tailscale', hours? }`, `{ action: 'stop' }`. The view carries the link and its QR code (the engine's own encoder, `money/qr.ts`). `PHONE_NO_NETWORK` when there is no Wi-Fi or Tailscale address, `PHONE_ACCESS_UNAVAILABLE` without a host listener, `TIER_UNAVAILABLE` on the hosted app.
- **Hosts.** The desktop worker (`platform/runtime/worker.ts`) and the local web server entry (`server.ts createServerEngine`) pass the port as `venture.phoneAccess`; the hosted app gets none.
- **Web client** (`app/ui/src/engine/client.ts`): reads `#pair=` once, removes it from the address, trades it once at `/api/phone/pair` (requests that start together wait for the one trade), keeps the session in memory only. A used or expired link shows the engine's words and asks for a new link.
- **UI.** Business > Notifications, "How alerts reach you", a closed fold **Phone access**: Make a pairing link (QR code and the link), Link for Tailscale (only when this computer has a Tailscale address), Stop phone access.
- **Fake engine**: a computer at 192.168.1.20 with no Tailscale; same codes, words and checks; a sample link and its QR code; nothing listens.
- **Guide**: `docs/venture/phone-access.md`, for 6J4 to link: same Wi-Fi pairing, the Windows private-network prompt, plain http on home Wi-Fi only, and the Tailscale section (install on both, same account, the 100. address, Link for Tailscale, the computer must be awake).

## Deviations and why

- The `app/companion/` signed device protocol (`/api/companion/rpc`) was not used: it needs a native app with device keys. The plan says "pairing by link" for the browser, which the existing local server and member sessions already support.
- Plain http on the home network: no certificate a phone would trust exists for a LAN address. Tailscale encrypts its own traffic; the guide tells owners to use home Wi-Fi with a password only.
- Phone sessions live in the listener's memory: quitting Chausar or Stop ends them; a refresh on the phone needs a new link (the same rule as the paired desktop browser).

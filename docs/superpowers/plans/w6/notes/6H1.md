# 6H1 Mini apps (D39)

## What was built

- **The app as data** (`platform/runtime/venture/apps/`). One `venture-mini-app` record per app: its versions (the HTML the owner's AI wrote, a summary, what the code needs, the owner's words), the version in use, the grant, the pin, the app's own notes and the making chat. Code reads the needs from the code itself (`permissionsOf`: only the tools the code names) and refuses code that reaches outside or writes money (`appCodeFindings`: links to other sites, outside scripts, frames, forms, fetch and other network calls, storage, new windows, code from text, amounts like `₹500` or `Rs 500`), with the reasons shown to the owner (`APP_CODE_REFUSED`). Versions kept: 20.
- **Making an app** (`venture.apps.make { ask, app? }`, prepare, app only). The owner's words (and, for a change, the current name and code) go to the owner's AI through the normal chat route and chat consent (`chatCall`, purpose `chief-chat`, `containsClientData: false`). The AI answers with name, summary and HTML as data; nothing it wrote runs anywhere but the frame. Chausar's reply in the making chat is written by code from what the code uses. A change keeps the name, grant and notes; new needs ask again. No AI connected: `APP_NEEDS_AI`.
- **Permission screen** (`venture.apps.grant { app, digest }`, approve, app only; `venture.apps.revoke`). The digest binds the app, the version on screen and exactly the permissions it lists. Nothing answers before Allow. A version that needs more shows the screen again with the new items marked; what was allowed stays allowed, so going back a version keeps working. Turn off clears the grant.
- **The bridge** (`venture.apps.call { app, tool, arguments }`, prepare, app only), in the MCP CallToolResult shape. Tools and the permission each needs: `clients_list` (names only), `orders_list`, `invoices_list` (each balance as a display with a statement sum receipt, no raw amounts), `notes_get` / `notes_set` (the app's own notes, bounded: 500 keys, 20,000 per note, 100,000 in all), `calculate` (add, times, percent-off in BigInt minor units with a new sum receipt subject `app-calc`; the app gets the display and the receipt id only), `propose` (draft-reminder or draft-invoice: a `venture-proposal` with `source: 'app'` and `appId`, gate-checked, raised on Today at once and decided like any other; the same card twice answers "It is on Today already"; at most 10 open cards per app). Unknown tool `APP_TOOL_UNKNOWN`; before Allow or outside the grant `APP_NOT_ALLOWED`.
- **Versions with undo, pin, export, delete.** `venture.apps.restore { app, version }` answers `undo: { version }`; `venture.apps.pin { app, pinned }` answers `undo: { pinned }`; `venture.apps.export` gives one HTML file with the same policy and an offline bridge that says it has no data; `venture.apps.remove` deletes the record, every version and its notes (its Today cards stay).
- **The locked frame.** `public/mini-frame.html` is the sandbox proxy. The Ink app loads it in an iframe with `sandbox="allow-scripts"` (never allow-same-origin, so an opaque origin of its own), `referrerpolicy="no-referrer"` and an `allow` list that turns off camera, microphone, location, clipboard, payment and devices. The desktop serves that one path with `MINI_FRAME_CSP` plus `sandbox allow-scripts` as its header (`app/desktop/mini-frame.cjs`, used in `main.cjs`); every other file keeps the app's policy. The proxy writes the app document its parent sends, once, and keeps the policy. A new `will-frame-navigate` guard keeps every frame in the window on the proxy or the app's own blob previews.
- **Why not blob or srcdoc** (the plan's suggestion). A probe in real Electron 44 showed blob and srcdoc frames inherit the renderer's `script-src 'self'`, so an app's inline script never runs, and `data:` frames are refused by `frame-src`. The proxy is the MCP Apps spec's own sandbox-proxy pattern (`ui/notifications/sandbox-proxy-ready`, `ui/notifications/sandbox-resource-ready`), with a stricter sandbox: the spec's web host gives the proxy allow-same-origin on a separate origin; Chausar gives no same origin at all. `SitePreviewFrame` is reused as the pattern (sandbox attribute, no referrer, frame class), not as the component: its blob document cannot run scripts.
- **MCP Apps message format.** Spec: https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx (SEP-1865, `io.modelcontextprotocol/ui`, status Stable, version 2026-01-26; read on 1 November 2026; the only other folder is `draft`). The view side (`apps/frame.ts`, injected first into every app document) sends `ui/initialize` with `protocolVersion: "2026-01-26"`, then `ui/notifications/initialized`, `tools/call` and `ui/notifications/size-changed`, and answers `ui/resource-teardown`. The host side (`app/ui/src/places/apps/bridge.ts`) accepts only messages whose source is its own frame's window, answers `ui/initialize` (hostInfo Chausar, `hostCapabilities: { serverTools: {} }`, theme, inline display), relays `tools/call` only after initialized and only for allowed tools (refusals come back as tool errors in the engine's words), answers `ping`, refuses `ui/open-link`, `ui/message`, `ui/update-model-context`, `resources/read` and everything else with -32601 (no internet, no talking to the AI), ignores messages over 64 KB, caps 8 calls in flight, bounds the frame height, and closes on a second proxy start. Each version is named `ui://chausar/apps/<id>/v<n>` with type `text/html;profile=mcp-app`.
- **UI.** A new rail place, Apps, between Money and Connections (AppsA): the make box (the Composer, with three ideas), one card per app (summary, name, what it reads, pinned or version or "waits for you to allow it", Open), and what every app can and can't do. An app opens at `#/apps?app=<id>` (AppsB): the making chat, the app in its locked box (or "Allow this app to run it."), Pin to Today and Export, a box to ask for a change; beside it the permission screen, or what it may do with Turn off, its versions with Use and Undo, and Delete (asks first). Phone: Apps is in the More sheet. Today shows "Pinned apps" only when one is pinned (6H3's `apps` layout block), so Today at rest is unchanged.
- **Fake engine** (`fake-apps.ts`): the same methods, words, codes and checks; it has no AI, so make writes one sample app. Lumen Studio starts with one app, allowed and not pinned. `fake-chief.ts draftFromApp` raises the card; `fake-money.ts appInvoices` gives each balance with a receipt.

## Deviations and why

- **Making an app lives in Apps, not in Chats.** AppsB draws the making chat in the Chats place. Each app keeps its own making chat (the owner's words and Chausar's replies) shown when it is opened, reached from Apps and from Today's pin. Wiring a "make an app" step into the chief's chat would change Chats' proposals, gate and fake desk while 6G1 and 6I1 edit them. The founder may want a Chats entry point later.
- **Pin to Today goes through 6H3's layout.** The pin itself is `venture.apps.pin` on the app record. On Today, 6H3 added an `apps` block ("Pinned apps", fixed name) to its layout library and draws `PinnedApps` in it, so the owner can move or hide it like any block. `PinnedApps` draws nothing when no app is pinned, so Today at rest is unchanged. A `ui_pin_app` tool for the owner's AI is not built (6H3's `ui-tools.ts` could call `venture.apps.pin`).
- **App notes are not exact-approval writes.** D39 lists "keep its own notes" among what an app can do; the owner allows it on the permission screen. Every write to the business is a Today card the owner approves; the card then runs the method under its own gates and journal.
- **Model purpose.** Making an app uses the existing `chief-chat` purpose and tier, so no new model setting was added.
- **No "New" badge on the Apps rail item** (the mockup shows one): it would add words to every screen; left out.

## Open items

- **Forget a client** does not search mini app notes. An app that keeps attendance marks may hold a client's name in its notes; deleting the app deletes them. Forget should also clear matching notes (DPDP); not built here.
- **Hosted tier**: the hosted server serves `/app/` files with `frame-ancestors 'none'` and `script-src 'self'`, so the proxy would not run there. The hosted tier is outside the beta; it needs the same per-path policy as the desktop if it returns.
- **Export** uses the browser download (an anchor with `download`). On the desktop that is Electron's default save dialog; it was not run in the packaged app.
- **Fake parity limits**: the fake writes one sample app instead of asking an AI, does not ask for the chat consent before making, and its receipts use the fake money desk's display.
- **Words**: the Apps place at rest measures 121 words on the fake engine (one sample app); it is not in `budgets.test.tsx` yet. The integrator sets its budget with the founder. Today, Chats and every measured place are unchanged.
- **MCP server tools**: D40 says the same UI tools are in Chausar's MCP server; an `apps` tool for the owner's AI outside the app (list, make, pin) belongs with 6H3's `ui-tools.ts`.
- Method counts in `venture-method-hints`, `venture-contracts` and `venture-engine` need the integrator's single update (+10 methods).

# 6D3 Razorpay Payment Links (D25), fixture-tested

## What was built

- **Keys in protected storage only.** `venture.billing.set { razorpayKeys: { keyId, keySecret } | null }` (app only) saves the key id and secret together under the credential name `payments:razorpay` in the host's protected key storage (the same port as model keys; the name was added to `platform/runtime/venture/models/credential-contract.cjs`), or forgets them. The business file keeps only which account (test or live from the key id prefix, the last four characters, when saved). Tested that the secret never reaches the business file.
- **Create a link on exact approval** (`platform/runtime/venture/money/razorpay.ts`, `venture.invoice.payLink { invoiceId, action: 'create', digest }`, app only): the invoice view offers `howToPay.payLinkOffer` (amount, currency, digest of invoice + number + exact balance + currency). Creating goes through the action journal as a write to a connected service (operation `create-link`, already on the known list) and the policy gate bound to that digest, then `POST https://api.razorpay.com/v1/payment_links/` with Basic auth, the exact balance in minor units, `accept_partial: false`, the invoice number as reference, `notify: { sms: false, email: false }` (Razorpay messages nobody; the owner shares the link), expiry 30 days. The answer is checked field by field; a link for any other amount is refused. A 4xx is "not sent" with Razorpay's own words; a 5xx or no answer is "outcome unknown" (never retried by itself). One live link per balance.
- **Polling while the app is open** (`action: 'check'`): `GET /v1/payment_links/{id}`; each `captured` payment not seen before is recorded once through the normal payment path (`recordPaymentMinor`, method `payment-link`, its exact amount, received on the owner's local day of the payment time), with its books fact and the calculator's received receipt (`sealBooks`). The invoice sheet calls check every 30 seconds while a link waits; no webhooks.
- **Client copy** gains "Pay online: <short url>" while the link is live. Labels: every surface says **fixture-tested** (`BillingView.razorpayLabel`, `payLink.label`, `payLinkOffer.label`, the UI chip).
- **UI**: "Make a payment link" asks a second time ("Make a Razorpay link for <amount> on your own account? ...") before anything is sent; the link and its status show after. Keys are entered in the "How clients pay" sheet (Key Id, Key Secret as a password field; "Save keys", "Forget keys").
- **Fake engine**: same codes, checks and words; never reaches Razorpay, makes a sample link.

## Deviations and why

- No new journal action id: creating a link is recorded as the existing `connector.write` with operation `create-link`, which the journal already lists as "making a payment link". The policy gate name is `payment.link.create`, touching `send`.

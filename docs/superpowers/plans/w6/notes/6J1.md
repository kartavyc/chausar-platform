# 6J1 Installers (D3, D12, D36)

## What was built

- **A beta packaging mode**, `node scripts/desktop-package.mjs --mode beta` (`npm run package:beta`), next to preview and final. Config `app/desktop/builder.beta.json`, output `release/beta`. Product "Chausar", app id `in.chausar.desktop`, release channel `beta`, real data (not the synthetic preview), unsigned (no signing, no executable editing), no publishing, no update channel. Windows: an NSIS installer, per user, no admin, folder can be changed. Linux: AppImage and tar.gz. Mac refused. Native hosts only, like the other modes (a Linux build needs a Linux machine). `validateBetaConfig` refuses signing, publishing, the preview identity, other resources, hooks, per-machine installs and deleting the owner's data on uninstall.
- **Codex bundled with its LICENSE and NOTICE.** `scripts/codex-bundle.mjs` (`npm run package:codex -- --from <installed @openai/codex folder>`) copies the platform files of Codex 0.154.0 unchanged from a local npm install (no download) into `vendor/codex-bundle/<os>-<arch>` (git-ignored), adds `LICENSE` and `NOTICE` and writes `BUNDLE.json` (sha256 of every file). The beta build refuses to start unless that bundle verifies (right version and target, LICENSE and NOTICE byte for byte, no changed, missing or extra file). In the installed app it is `resources/codex`. The app puts `resources/codex/bin` last on the engine's PATH, so an owner's own Codex still wins.
- **Licence findings.** The npm package `@openai/codex` ships no LICENSE or NOTICE (its `files` is only `bin/codex.js`; the platform package only `vendor`). Both files were taken from github.com/openai/codex at tag `rust-v0.154.0` (identical to `main` on 1 November 2026): LICENSE is Apache-2.0 (sha256 `d17f227e...`), NOTICE names OpenAI and code derived from Ratatui (MIT). The Codex folder also carries ripgrep 15.2.0 (`codex-path/rg.exe`, Unlicense or MIT) built with PCRE2 10.45 (BSD-3-Clause with the PCRE2 exception, which asks binary copies to carry the notice).
- **Start at login and keep running in the tray** (`app/desktop/background.cjs`, wired in `main.cjs`). Installed beta only. Both are owner settings, default on, shown as ticks in the tray menu: "Start at login" and "Keep running in the tray". Kept in `background.json` in the app's own folder. Windows: Electron's login item, value `Chausar` under `HKCU\...\CurrentVersion\Run`, command `"<install>\Chausar.exe" --background --hidden`. Linux: `~/.config/autostart/chausar.desktop` (or `$XDG_CONFIG_HOME`), pointing at the AppImage file itself (`$APPIMAGE`) or the unpacked program. A login start opens no window; Chausar waits in the tray until opened. With "Keep running in the tray" off, closing the window quits as before. Previews and development runs never register a login item and their tray menu is unchanged.
- **Uninstaller** (`app/desktop/installer.nsh`): removes the `Chausar` Run value, its StartupApproved switch and `%LOCALAPPDATA%\chausar-updater`. The owner's data in `%APPDATA%\Chausar` stays.

## Install steps (for 6J4)

Files (version from `package.json`, today `0.1.0-preview.1`):
- Windows: `Chausar-Beta-0.1.0-preview.1-win-x64.exe` (about 309 MB; Codex is about 381 MB unpacked).
- Linux: `Chausar-Beta-0.1.0-preview.1-linux-x64.AppImage` and `Chausar-Beta-0.1.0-preview.1-linux-x64.tar.gz` (not built yet; see open items).

Windows:
1. Open the `.exe`. Windows SmartScreen says it protected your PC (the installer is unsigned): click "More info", then "Run anyway".
2. The installer installs for you only (no admin). It shows the folder (default `%LOCALAPPDATA%\Programs\Chausar`); you may change it. Click Install.
3. It adds "Chausar" to the Start menu and the desktop and opens Chausar at the end. The first screen is "Connect your AI".
4. Chausar starts when you sign in to Windows and sits in the tray (bottom right, near the clock). Closing the window keeps it running there. Right-click the tray icon for "Open Chausar", the ticks "Start at login" and "Keep running in the tray", and "Quit Chausar and stop jobs".
5. Uninstall: Settings, Apps, Chausar, Uninstall. It removes the program, the shortcuts and the start-at-login entry, and keeps your businesses in `%APPDATA%\Chausar`.

Silent install for testers: `Chausar-Beta-<version>-win-x64.exe /S /currentuser /D=<folder>` (`/D=` last, no quotes); silent uninstall: `"<folder>\Uninstall Chausar.exe" /S /currentuser`.

Linux:
- AppImage: `chmod +x Chausar-Beta-*.AppImage`, then run it. It needs FUSE 2 (`libfuse2`, on Ubuntu 24.04 and later `libfuse2t64`); without it, `./Chausar-Beta-*.AppImage --appimage-extract-and-run`.
- tar.gz: `tar -xzf Chausar-Beta-*.tar.gz`, then run `./chausar` inside the folder.
- Start at login writes `~/.config/autostart/chausar.desktop`. There is no uninstaller: untick "Start at login" in the tray menu (or delete that file), then delete the AppImage or the folder. Your data is in `~/.config/Chausar`.
- Codex is included in both Linux files once they are built on Linux (see open items).

## Deviations and why

- **A new `beta` mode instead of changing preview or final.** The preview is the synthetic-data demo and forbids extra resources (so it cannot carry Codex); final demands signing and vendored runtimes. D3 says unsigned for now.
- **Lockfile gate, one pinned exception.** The gate had never passed with electron-builder 26: its dependency `@electron/node-gyp` is a Git source (`git+ssh://...node-gyp.git#06b29aaf...`), which the "HTTPS registry only" rule refuses (`docs/requirements/integration-state.json` already noted this). I allowed exactly that path and commit, dev-only, still with its integrity hash; anything else is still refused. Founder or integrator should confirm this policy change.
- **Root `package-lock.json`.** The stray one (23 October) no longer matched `package.json`. For the build I rewrote it from npm's own record of the installed tree (`node_modules/.package-lock.json`) plus the root entry, and added `@mozilla/readability@0.6.0` (installed today but missing from that record; integrity from `npm view`). It is still untracked; do not commit it (AGENTS.md). The old file is saved at `C:\Users\karta\AppData\Local\Temp\claude\D--claude-chausar-2\0016102d-af13-47b9-a6f2-73a8e1737d87\scratchpad\package-lock.stray-2026-10-23.json`.
- **File sets in the beta config.** electron-builder 26 puts every unpacked file of a mixed file set into one pattern, and `@electron/asar` refuses patterns over 64 KB (1,689 files under `platform/runtime`). `platform/runtime`, `platform/semantic-qualification/src` and `platform/helpers` are their own file sets in the beta config. The preview config has the same problem and was left alone (out of scope).
- **`signAndEditExecutable: false`.** Editing the exe needs electron-builder's winCodeSign download; so `Chausar.exe` and the installer keep Electron's icon and version details.
- DECISIONS names the VPS user `fable`; the brief named `chausar-test`. I followed the brief.

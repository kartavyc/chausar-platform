# 6H3 UI as data and AI tools (D40)

## What was built

Engine:
- `platform/runtime/venture/views/layout-core.ts` (new, pure, also imported by the fake): the block library, the rules and the words.
  - Today: greeting (keeps: questions), notices (keeps: stops and pauses), goal (keeps: money), team, needs you (keeps: approvals), working now, earlier, ideas, pinned apps (6H1's block; no rename).
  - Money (overview): money at a glance (keeps: money), owed and cash ahead (keeps: money), the "In and out" fold, the "Due soon" fold.
  - A layout is data: the order of the movable blocks, the hidden ones, names, and up to 5 saved views. No code, styles or markup. A stored layout that no longer fits the library is read back as far as it fits (unknown ids dropped, a new block placed last and shown, a name that no longer passes dropped).
- `platform/runtime/venture/views/layout.ts` (new): one `venture-layout` record per change (the newest is in use), per owner (member) and place.
  - `venture.layout.get { place }` (read) answers the blocks in draw order, saved views, `custom`, `ai` (every AI change since the owner's own last one, up to 3 lines, with one Undo) and `go` (the AI's latest request to open a place).
  - `venture.layout.change { place, change }` (prepare, app only) is the owner's change. Ops: hide, show, move, rename, save-view, use-view, delete-view, reset, restore (Undo) and keep (owner only).
  - Every change returns `{ layout, undo, line }`; `undo` is the exact request back to the layout before it. Each emits `queue.changed` (no words), so open screens read again.
- `platform/runtime/venture/agent-runtime/ui-tools.ts` (new): five MCP tools, stored as made by the AI: `ui_read_screen`, `ui_arrange` (show, hide, move, reset, restore), `ui_rename`, `ui_views` (save, use, delete), `ui_navigate`. Each checks its own closed schema too.
- The pinned toolbox list `AGENT_MCP_TOOL_NAMES` (driver-types.ts) now has the five UI tools, with a comment. Every job toolbox carries them (native-job.ts), because Codex refuses a server whose tools differ from the pin.
- Registered in contracts (record kinds and types, methods, owners, app-only, params, results), records.ts prefixes, method-hints, engine.ts, views/index.ts and the desktop IPC allowlist and its `.d.cts`.

Guardrails (all in layout-core.ts, so the owner, the AI and the fake get the same):
- Blocks that hold an approval, a question, a stop or a money total always show, keep their slot and keep their name (`LAYOUT_LOCKED`). The UI also draws them whatever the layout says.
- A block with figures takes only one of its listed names (`LAYOUT_FIGURE_NAME`).
- Other names are plain words: no digits, no money words, no other block's name, and no more words than the block's own name (`LAYOUT_NAME`). Every block is shown by default. So a changed layout never shows more words at rest than the library's own, and no budget can be lifted by a layout change.
- The AI cannot keep its own changes; the owner sees them with Undo and Keep. Layout tools never touch settings, approvals, limits or receipts.

App:
- `app/ui/src/parts/layout/`: `useLayout` and `drawnBlocks` (until the layout comes, or if the read fails, the library's own layout), `LayoutNotice` (the AI's lines with Undo and Keep), `ArrangeButton` (an icon in the page tools, name for screen readers only), `LayoutSheet` (sheet `layout:<place>`), `AiGo` (opens the AI's newest place request once, says so, Go back).
- Today and Money's overview draw their blocks in slots: locked blocks in their own slots, the others in the owner's order. Each block sits in a `display: contents` wrapper, so the default page lays out exactly as before. Renamed headings reach TeamAtWork, WorkingNow, Earlier, IdeasFold and the Money folds through a `title` prop. If Ideas is hidden, "Waiting on you" still shows. If one of Working now or Earlier is hidden, the other takes the whole row.
- Fake (`fake-layout.ts`): the same methods through layout-core. `engine.layoutDesk.ai(...)` and `.go(...)` stand in for the MCP tools in tests and the demo.
- Text: `app/ui/src/text/en/layout.json`.

## API for other packages (6H1 pin to Today)

- Pinned apps are already a Today block (`apps`, movable, can be hidden, not renamed). Today draws `<PinnedApps />` in that slot.
- To add a block: append `{ id, name }` to `LAYOUT_LIBRARY.<place>.blocks` (add `keep` if it must always show, `aliases` if it shows figures, `fixedName` if it has no heading). Then draw it in the place's `blockContent` and add a `slot(n)`. Old layouts pick it up shown and last.
- Engine: `changeLayout(deps, ctx, place, change, 'owner' | 'ai')` and `layoutView(state, venture, memberId, place)` in views/layout.ts. UI: `useLayout(place)`, `drawnBlocks(place, view)`.

## Deviations and choices

- D40 says changes touching approvals, privacy, money rules or limits become a Today card. The layout tools cannot reach those: the blocks that carry them are locked, and the tools change no settings. So no Today card path was needed. A request to hide such a block is refused in plain words.
- Navigation is stored as data (`venture-layout-go`). The app opens it once, only when it is newer than the request the window found at start, and offers Go back. No new event type: `queue.changed` carries the refresh, because a new run event would widen the desktop and web event contracts.
- `ui_read_screen` takes a place. The engine does not know which page the owner has open.
- Start small: Today and Money's overview only. Other places answer `LAYOUT_UNKNOWN_PLACE`.
- The reference UI has no drawn layout screen (Main.dc.html is "Connect your AI"). The sheet follows the current sheets, with quiet buttons and no new colours.
- Layout records are append-only, like 6G1's settle records. There is no pruning yet.

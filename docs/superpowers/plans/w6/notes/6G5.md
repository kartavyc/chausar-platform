# 6G5 Spend meter and model receipts (D44)

Fixture-tested. The package reads records the 6B2, 6B3 and 6B4 drivers and billing already write, and adds one route note when a native job starts. It never calls Codex, Claude or a provider itself (reason below).

## What was built

**Routine attribution.** `agents/routine-scope.ts` holds the routine run that the current work belongs to, using Node's AsyncLocalStorage. Run it in `routine-runner.ts` sends the prompt inside that scope. The model port (`models/port.ts`) then writes `routineId` and `routineRunId` on the call record, and `routine` on its charge (`SpendRecord.routine`, through `SpendSubject`). No chat path had to carry a new id.

**Owner cap per routine.** `SpendPolicyRecord.routineCaps` is set through `venture.spend.policy.set { routineCaps: [{ routine, capUsd }] }`, in the app only. A routine id that isn't live is refused. The list replaces the one in force, so an empty list clears it. Agent caps (4F2 `agentCaps`) are unchanged and now reach the screen.

**Refused before it starts, with the reason.** On a key route, `routineStartRefusal` (`money/agent-meters.ts`) checks three limits: the routine's own, its agent's, and the month's.
- The sweep skips a due run with "Skipped: <reason>", and no card parks.
- Run it on a card that is already waiting throws `SPEND_CAP` with the reason. Nothing is sent, and the card keeps waiting so the owner can raise the limit.
- Inside a run, `reserveSpend` also refuses any paid call that would pass the routine's limit (`routineCapRefusal`, `SPEND_CAP`, "... Other work goes on.").
- A routine on the owner's plan isn't held, because Chausar counts no money for it.

**Meter per agent and per routine.** `SpendPolicyView.meters` (`spendMeters`) has one row for each team agent (plus any off-team agent that spent this month, shown as "(retired)") and one for each routine. Each row has:
- this month's spend from the charge records, in the currency that leads (4Z3), with a new `spent-by` sum receipt (registered in `sums.ts`)
- plan runs ("2 runs on your plan"), never priced and never in rupees
- the owner's cap, its share used, paused, and a plain line

**Model receipt on every run.**
- `RunDetail.modelReceipt` comes from `venture.runs.get` for delivery runs (`money/model-receipt.ts`). A native job records `agentJob.route` (preset, model, main tier) when it starts, using `AgentRoute.presetId` from `selectAgentRoute`. Its cost is billing's priced figure and receipt, or "On your plan".
- Older model runs use their call records and charges, with a `spent-by` run receipt.
- Template and owner-copy runs say "No AI · No cost".
- `RoutineRunView.receipt` comes from the run's calls (tool, model each answer named, tier, summed tokens). Its cost has a `spent-by` routine-run receipt.

**UI.**
- Money > Spend: a quiet icon button beside the Paid calls total ("Spend by agent and routine") opens the rows, each with a receipt mark and a Set a limit / Change limit field in US dollars.
- `parts/ModelReceipt.tsx` sits in the run sheet and in each routine run's history.
- The fake engine matches: meters and caps (`fake-extras.ts`), receipts (`fake-model-receipt.ts`) and sample sum receipts R-0451 to R-0454.

**Sunra (6F9).** Approved or submitted generations show on the agent's row as "Images and video: up to USD x, quoted by Sunra". They aren't held against the cap, because each one already has its own exact approval card with the code-computed cost.

## Deviations

- **Meters placement.** The rows sit behind an icon button, not a labelled fold. A five-word fold summary took money/spend to 155 words against a budget of 150, and budgets may only go down. The button carries its name for screen readers and as a tooltip.
- **Two existing tests were extended.** venture-spend-policy now strips the new `meters` field. The business-routines history expects the receipt under a delivered run.
- **Split modules.** `spend-meter.ts` (loaded by spend.ts) is kept apart from `agent-meters.ts` (which reads team names). Loading chief/routing from spend.ts caused a start-up import cycle (`YOUTUBE_STEPS` before initialization).

## Open items

- **Retired names.** Retired agents read as "<name> (retired)" through `chatAgent`, with a suffix matching 6G2's `RETIRED_SUFFIX`. 6G2 may want to reuse its own constant.
- **Fake engine gap.** The fake's Run it doesn't apply routine caps, because the fake keeps no routine spend. Its meters and receipts are sample data shaped like the engine's.
- **Not exact before the call.** "Would pass the cap" is checked against what is already spent or held. A single call is checked at its estimate, and provider costs reported later can still overshoot, as noted in 6B4.

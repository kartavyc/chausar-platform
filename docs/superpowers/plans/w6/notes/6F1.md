# 6F1 MCP client (D30)

Builds on the Batch 2 client (`external-client.ts`, `external-mcp.ts`, `external-config.ts`, `external-credentials.ts`). There's still one client and one proxy. Reference read: Codex `core/src/mcp_tool_call.rs` and `rmcp-client/src/perform_oauth_login.rs`. Codex trusts `read_only_hint` in its auto mode and has no description fingerprint. Chausar never trusts a server's own hints.

## What was built

- **Transports.** stdio (desktop and test hosts only; `MCP_STDIO_DESKTOP_ONLY` elsewhere) and streamable HTTP, through the official SDK as before. A stdio server can name the one variable its saved key arrives in (`tokenEnv`, default `MCP_AUTH_TOKEN`). System and code-loading names like PATH, NODE_*, LD_* and ELECTRON_* are refused.
- **OAuth with PKCE** (`mcp-oauth.ts`, new method `venture.mcpOAuth.start`, admin, app only). An HTTP server marked `oauth: true` signs in through a one-time listener on 127.0.0.1. The SDK handles discovery, dynamic registration as a public client, an S256 challenge, a state check that uses a constant-time compare, and the code exchange. Tokens go only to the credential port, as a JSON envelope under `mcp:<venture>:<server>`, never into settings or records. Jobs refresh through the same storage. If a job needs a fresh sign-in it fails with `MCP_SIGN_IN_REQUIRED` and never opens a browser.
- **Elicitation** (`mcp-elicitation.ts`). The client declares elicitation only. It never declares sampling or roots. A form question becomes an `external-input` card in the existing approval journal (`requestAgentInput` in `approvals.ts`), and the owner's answer rides on `venture.agentApproval.decide { content }`, checked against the exact form. Questions asking for passwords, keys, OTPs, card, bank, PAN or Aadhaar numbers are declined without asking, and so are link-mode requests. Today shows the question with Read and Decline only, so a bare Approve can never answer it.
- **Checked read-only list** (`mcp-policy.ts`, `CHECKED_READ_ONLY`). A listed tool runs without a card. Each one is pinned to its exact server (HTTPS URL, or the npm package run by npx), name, description (exact text or its sha256) and input field names. Any change drops the tool off the list, so it asks again. The list holds Microsoft Learn's three tools (pinned from the live call) and Sunra's five read tools.
- **Exact approval for everything else.** The card now carries `argumentsDigest`, the sha256 of the canonical arguments. Dispatch sends the approved input and rechecks the digest (`MCP_ARGUMENTS_CHANGED`). A changed tool fingerprint asks again, as before.
- **Untrusted output.** Every result is marked `untrusted` with a data-only notice. Once outside output has come back, later cards carry `afterOutsideContent: true`. No output can approve or start anything.
- **Tool search.** Above 40 tools, an empty query returns only the count and a hint. Searches are ranked and capped at 20 results.
- **Curated list** (`mcp-registry.ts`, new method `venture.mcpRegistry.list`, read). Five servers from registry.modelcontextprotocol.io, latest version, checked 1 Nov 2026: Microsoft Learn (no sign-in, read), Notion, Canva, Linear and Zapier (OAuth, write). Adding one only fills the form; saving still needs the exact configuration approval.
- **UI** (inside the closed AI settings fold, so no word budget moves): a "Sign in with the service" checkbox and a Sign in button, a key-variable field, a Suggested servers fold, the question card and a cost figure on run cards. Fake engine parity covers all of it: same codes and order, with OAuth stopping at `CREDENTIAL_UNAVAILABLE` because the demo has no protected storage.

## Public API for other packages (6F8 and others)

- **Register a server:** an `ExternalMcpServer` (`external-config.ts`). For HTTPS use `{ id, name, transport: 'http', url, oauth?: true }`. For a local program use `{ id, name, transport: 'stdio', command, args, tokenEnv? }`. Keys go in with `venture.mcpCredential.set`; OAuth uses `venture.mcpOAuth.start`.
- **Add per-service rules:** write an `McpCallAdapter` (`mcp-adapters.ts`) and add it to `DEFAULT_MCP_ADAPTERS`. `plan()` can throw to refuse a tool, or return `{ card, description, approved, declined, settled }`. Card fields join the approval digest, and a plan with a card always asks. Example: `media/sunra.ts`.
- **Mark a tool read-only:** add an entry to `CHECKED_READ_ONLY` (`mcp-policy.ts`), pinned as above, only after reading the real tool list.
- Jobs reach all of this through the existing `external_tools` and `external_call` proxy tools. Nothing else is exported for jobs.

## Deviations and open items

- **Desktop browser open.** The desktop's `openExternal` allows only listed partner origins, so an OAuth address for an owner-added server is refused there. For now the UI shows the sign-in link for the owner to open. The integrator should decide on an engine-vouched open path in `app/desktop` (ipc-contract `EXTERNAL_ORIGINS` / main.cjs).
- **OAuth live.** Only fixture-tested, against a local server with real PKCE. A real OAuth service needs the founder's own account (Notion, Canva or Linear).
- **Audit.** Free reads write no audit row; they return `approval: 'checked-read-only'`.
- **Boundary label.** `AI_SETTING_BOUNDARIES.externalMcp` still says `approval-required`. The settings and connections strings now say "Only checked read tools skip asking you". The label key wasn't renamed, to keep the 6B7 contract.

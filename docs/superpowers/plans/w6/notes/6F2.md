# 6F2 Playbook packs (D31)

## What was built

- **Format** (`platform/runtime/venture/packs/pack-format.ts`, browser-safe and shared by the fake engine). A pack is one `chausar-pack/1` JSON document with three parts:
  - `skills`: markdown, up to 20.
  - `mcpServers`: references, up to 10, checked with the 6F1 server validator.
  - `calculators`: up to 10.
  Anything else is refused. Code-hook names (hooks, scripts, onInstall, bin, main and the like) get `PACK_CODE_REFUSED`, unknown parts get `PACK_INVALID`, and so do saved credentials in a server reference. Script or iframe markup in a skill is refused too.
- **Calculators.** Each one is a WebAssembly 1 module checked byte by byte. It has no import section, no start section, no tables, and at most one memory with a declared maximum within `maxMemoryPages` (16 at most). Its only exports are `run` and optionally its memory. `run` takes exactly one i64 per declared input and returns one i64. Anything else gets `PACK_WASM_REFUSED`.
- **Folder loading** (`loadPackFolder`). Reads `pack.json`, `skills/<id>.md` and `calculators/<id>.wasm`. Any other file, folder (such as `hooks/`) or link is refused before anything is read.
- **Methods**, all in the models package:
  - `venture.packs.list` (read).
  - `venture.packs.add { pack, digest? }` (approve). Without a digest it returns the exact preview. With the preview's digest, inside the app, it adds the pack; a changed pack gets `PREVIEW_CHANGED`.
  - `venture.packs.remove { packId }` (approve, app only).
  A pack is stored as a new `venture-pack` record. Adding one records a decision. Its server references are never added to AI settings.
- **Running.** `runPackCalculator` runs each call in a child process under Node's permission model, readable only by its own worker (`pack-worker.mjs`), with a 32 MB heap and a deadline. Traps, endless loops and malformed answers get `PACK_CALCULATOR_FAILED`.
- **Receipts in jobs.** Native jobs list pack calculators as `pack_<pack>_<calculator>`. The answer is stored as a work receipt with operation `pack.calc` (added to the `WorkReceiptRecord` union), naming the pack, version, module digest and inputs. Only the answer is a citable figure, and the draft guard accepts it like other receipts. `read_business` gives the AI the pack skills, labelled `owner-added pack`, through the existing untrusted screen.
- **UI.** An "Add-on packs" fold sits inside the AI settings fold. It shows the chosen file's exact pack first, then "Add this pack". Each pack lists skills, calculators and server suggestions, with a Remove button. The fake engine matches the engine's checks, digest and refusal codes (`app/ui/src/engine/fake-packs.ts`). The demo never runs a calculator.

## Deviations and open items

- A pack is one JSON file in the app, not a folder. Folder loading exists for bundled or developer packs; the UI doesn't offer it yet.
- Calculator inputs come from the AI as text integers. The receipt records them "as given", so an answer is only as good as its inputs. Pack calculators don't read order files. That could come later.
- Server suggestions in a pack are shown as text. Adding one means typing it into the server form, which then goes through the normal exact approval. There's no one-tap copy yet.

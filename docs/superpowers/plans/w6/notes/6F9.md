# 6F9 Images and video through Sunra (D38)

Fixture-tested only. No Sunra key exists, and no paid call or any call to Sunra was made.

## What was built

- **Server reference** (`platform/runtime/venture/media/sunra.ts`). Sunra's own MCP server, `npx -y @sunra/mcp-server@0.1.2` (stdio, desktop). The owner's key comes from protected storage as `SUNRA_KEY` (6F1 `tokenEnv`). Tool names, descriptions and fields were read from Sunra's public source (sunra-ai/sunra-clients, mcp-server 0.1.2): submit, subscribe, status, result, cancel, list-models, search-models, model-schema, upload, set-sunra-key.
- **Adapter** (`sunraAdapter`, listed in 6F1's `DEFAULT_MCP_ADAPTERS`). It recognises the npm package only when npx runs it.
  - `submit` and `subscribe` count as one generation each and get exactly one card.
  - `status`, `result` and the model lookups are on the checked read-only list (no card).
  - `cancel` and `upload` get a normal exact card.
  - Refused before any card: `set-sunra-key` (`SUNRA_KEY_TOOL_REFUSED`); any auto-confirm style argument at any depth, such as auto_confirm, skipConfirmation, confirm, yes or force (`SUNRA_AUTO_CONFIRM_REFUSED`); webhooks (`SUNRA_WEBHOOK_REFUSED`); and more than one image or video per request (`SUNRA_ONE_PER_APPROVAL`).
- **Rupee cost from code** (`quoteSunra`). It reads Sunra's published price card for the endpoint (the public, no-key `api.sunra.ai/v1/pricing/...`, fetched by code, never by the AI). The first rule that matches the request is used; operators `$size`, `$size_lte`, `$size_gte`, `$lte`, `$gte` and `$in` are supported, and an unknown operator refuses with `SUNRA_QUOTE_UNAVAILABLE`. For usage-settled endpoints the card uses Sunra's maximum reserve and says "up to". The cost is the dollar amount in micros times the owner's own rupee rate from Money > Spend, rounded once to the nearest paisa. With no rupee rate set, there's no card (`RUPEE_RATE_REQUIRED`).
- **Receipt and rights.** Each quote is stored before the card as a `venture-media-generation` record, and its id is the card's `receiptId`. The record holds the rule matched, the dollar amount, the rate and its date, and the paise. It moves from quoted to approved to submitted (with Sunra's request id), or to failed or declined. The rights record is built by code: AI-made output for this client's order, labelled as AI-made wherever shown. Any reference image or video URL needs the rights the owner recorded at intake, otherwise `RIGHTS_REQUIRED`.
- **UI.** The run card shows the cost as a figure with its receipt mark beside the exact arguments.

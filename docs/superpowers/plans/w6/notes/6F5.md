# 6F5 Email through the tool's Gmail connection (D34)

## What was built

- **Owner setting.** AI settings gain `connectors?: boolean` per tool (`agent-runtime/settings.ts`). It is off by default, validated as a boolean, and passed to the driver only when true. Saved settings without it read as before.
  - The UI adds one checkbox per tool inside the folded AI settings: "Let Codex use the Gmail you connected in ChatGPT. Every send still asks you." and the same for Claude. The fake uses the engine's own validator.
- **The policy** (`agent-runtime/connector-policy.ts`). It covers Gmail only, and tools are sorted by name, never by the tool's own hints.
  - On: making a draft and sending (Codex `send_email`, `send_draft`, `create_draft`; Claude `send_message`, `reply`, `create_draft`). Each always asks the owner.
  - Off: everything else, reading the mailbox included, along with deleting, archiving, labelling and forwarding.
  - Connectors are used only with a plan login, never with an API key.
- **Codex driver.** With connectors on and a ChatGPT login:
  - Feature flags: `features.apps` and `tool_call_mcp_elicitation` are on, `mcp_elicitations` is on in the granular policy.
  - Apps config: `apps._default` is disabled with the owner as reviewer and `prompt` mode.
  - Gmail (`connector_2128aebfecb84f64a069897515042a44`): enabled with `approvals_reviewer: user`, `destructive_enabled: false`, `default_tools_enabled: false`, and only the listed tools at `prompt`.
  - Every Gmail account link found at startup also gets the owner as reviewer, because a link's own setting comes first.
  - Startup check: what is callable is read from `app/installed` for the thread, and Gmail must be the only callable app. The apps server's inventory lists the whole account catalogue, 923 tools here, so it cannot be used for this.
  - At run time:
    - A started Gmail write item is held.
    - Codex's ask (an MCP elicitation, `codex_approval_kind: mcp_tool_call`) is matched to that one item and becomes a `connector-send` exact approval card with the item's full arguments. Approve answers accept once; anything else declines.
    - Asks that match no item, are ambiguous, come from another server or connector, or name a tool that is off are declined with no card.
    - Any automatic-review start on a connector call stops the job, and so does a write that completes without approval.
- **Claude driver.** With connectors on and a Claude login:
  - Setup: `ENABLE_CLAUDEAI_MCP_SERVERS=true`, `disableClaudeAiConnectors: false`, and `strictMcpConfig` off (see Deviations).
  - Gmail servers named in the init message are pinned to per-action prompts (`setMcpPermissionModeOverride(name, 'default')`), so the auto-mode classifier cannot decide a send.
  - Until a server is pinned, its writes are refused in auto mode. After that, the hook sends them to `canUseTool`, which raises the same `connector-send` card whatever the routine-review setting is.
  - Trust is keyed on `source === 'claudeai'`. Every other connector tool is refused.
- **Card, prompt and approvals.** `approvals.ts` accepts the new kind.
  - Today names the row "Approve one send", with the line "Read the exact message first. Approving sends it once through your own connection." (`views/queue.ts`). The run card label is "Send through your connection".
  - The job prompt (`runner.ts`, `jobPrompt`) gains one exception, only when on: send exactly the proposed handoff with the Gmail send tool.
- **Fallback.** Owners without a connection keep the existing path: `propose_action` makes a ready draft that the owner opens in their own mail app. That path is unchanged.

## Deviations

- **Reads are off.** Reading the mailbox would put other people's mail in front of the AI without their recorded consent, so only draft and send are enabled. This narrows the brief's "turn on connectors".
- **Claude needs strict MCP off.** Its strict MCP mode drops claude.ai connectors, so strict is relaxed only when connectors are on.
  - As a result, every claude.ai connector the owner has (25 here) becomes visible to the model, but Chausar refuses every tool call except the Gmail draft and send tools.
  - `managedSettings.allowedMcpServers` removed all claude.ai connectors, whichever names were tried.
  - `toggleMcpServer` could narrow the list to Gmail, but it may write to Claude Code's own config, so the driver does not use it. My one live toggle trial ran in a temporary folder.
- **Claude pinning is by name.** It pins any server named with "gmail" from the init list. Trust at call time is keyed on `source`.
- **Correlation can fall back.** Codex's ask is matched to its item by exact arguments. If Codex shows a rendered form, a single waiting item of the same tool is used. With two or more, it declines.

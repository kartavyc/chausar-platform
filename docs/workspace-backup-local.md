# Experimental local encrypted backup v2 custody

`platform/runtime/workspace-backup-local.ts` supplies actual Vault and filesystem ports for `WorkspaceBackupV2Host`. This is new source work, not release, enterprise, external-custody, native-storage, or full-workspace-portability qualification. It currently admits `experimental-file` storage only. PostgreSQL returns an adapter-issued envelope rather than original persisted envelope bytes and requires a separately reviewed custody profile.

Actual Engine/RPC integration is not implemented by these three files. The constructor ports require a separate trusted root join; their focused tests do not establish desktop route availability or release qualification. `fullWorkspacePortable` remains false.

The trusted constructor requires an already unlocked Vault, its canonical direct-parent application directory, all six v2 codec budgets, filesystem file/byte/depth budgets, explicit external key requirements, a current complete-owner/source/readiness assertion, and a mandatory `withCompleteOwner` admission capability. The latter holds actual owner/epoch/readiness exclusion through filesystem publication and supplies a synchronous `assertCurrent`. Root may use snapshot-only `Vault.withCustodyWriterAdmission`; an assertion alone cannot establish continuous external/backend readiness. Constructor capabilities and physical paths must never come from RPC payloads. In particular, root must declare `other / operator/credential-wrappers`: the archive contains encrypted key wrappers, but does not include a passphrase or recovery credential. An active keychain hook additionally requires a separate keychain requirement. No key material is returned, and neither capture nor restore mounts a historical State.

`Vault.captureEncryptedCustody` and `Vault.authenticateEncryptedCustody` run only under the Vault snapshot fence. Capture retains the exact UTF-8 authority bytes and every authenticated ciphertext file in both typed private namespaces. It includes private fork/evaluation bodies, active/discarded/promoting/promoted bindings, interchange archive copies, independent pins, issuance bindings, tombstones, target reservations, and previous v2 backups. Unknown private purposes or entries refuse capture. Wrapper field order, whitespace and ciphertext bytes are preserved because v1 authority authentication depends on the original wrapper insertion order.

The source fence compares authority, complete private enumeration, exact physical file hashes/measurements, source directory identity, wider directory identities, current owner/source grants, and the trusted readiness guard. Only the operation's exact newly written encrypted controls and its own physical process locks/staging file are accepted as controlled changes. Existing controls are captured and compared. Every introduced control is checked by authenticated readback plus its measured ciphertext hash; deleting a control records its absence. Exceeding a budget rejects the operation rather than truncating the inventory.

The actual source root is enumerated. `reports`, `plugin-assets`, `research-evidence`, `conversation-files`, and `sync-evidence` are hashed and measured, then explicitly classified outside the archive when populated or empty when empty. Source-identified files in application `backups`/`exports`, and application `updates`, are also measured outside the archive; unrelated backup/export identities refuse rather than reading their bodies. Writer and interchange/backup process controls are measured transient custody requiring new process ownership. Controls must have reviewed record/target sections and process-lock names; orphan staging or unknown administration refuses. Previously reserved v2 inert targets are measured separately outside the archive. Thus every successful source pin states `fullWorkspacePortable: false`; wider files are not silently represented as archive entries.

Unknown application siblings refuse capture. A trusted `outsideApplicationNamespaces` declaration describes external scope, but this measured codec cannot encode an unknown descendant count or byte total. Consequently an actual declared external sibling still refuses with `BACKUP_EXTERNAL_ENUMERATION_REQUIRED`. The adapter does not read another workspace's descendants or invent zero measurements. Root needs an independently authorized external inventory and an extended reviewed profile before such a layout can qualify. Interchange target siblings likewise require their own root inventory/admission; this adapter does not adopt an unrelated directory.

Each issued record uses three independently encrypted Vault artifacts in `workspace-interchange`: `wb2_<record-id-sha256>_archive`, `_pin`, and `_binding`. The binding is created with compare-and-swap create-only admission in `preparing` state before payload publication, binds creation/context/archive/pin digests and exact encrypted refs, then changes to `committed`. Archive and pin are read and authenticated independently. Failed creation revokes its exact issuance and removes only its own payload ciphertext, retaining a `discarded` tombstone. Committed, discarded and orphaned record IDs are single-use across process restart. Promise rejection never proves a write failed: each encrypted write resolves through exact authenticated readback, including completed writes whose acknowledgements were lost. Discard uses exact creation and both reviewed digest pins.

`custodyMeasurement(recordId)` reports actual encrypted archive, pin, binding and total retained bytes, plus removed ciphertext bytes. Generic host summaries expose archive/pin measurements; the local measurement includes issuance/tombstone overhead. `diagnostics()` exposes hashes, physical identities, measured sizes, namespace requirements and timing, without raw ciphertext or secrets.

Inert restore allocates a new empty directory under the canonical application root and saves an encrypted `wbt2_<target-id-sha256>_reservation` binding its source/current owner, physical identity, location and generation. Existing directories cannot be adopted, even when empty. Actual directory entries must initially be zero: no authority, private artifacts or wider content. The source authority queue and exclusive target process lock remain held through publication and readback.

Restore authenticates the entire archive with the current source Vault key, stages and syncs one `chausar.backup-inert-container.v2` file outside the empty target, verifies exact staging bytes and the full embedded archive, then checks source/owner/readiness/empty-target fences under held `withCompleteOwner` admission immediately before publication. Synchronous admission is checked directly before the filesystem operation and after exact physical readback. A hard-link create publishes `backup.inert.json` without overwriting an existing path; the temporary link is removed before readback. Lost link acknowledgements can be recognized only through the exact staging inode, never through a same-content unrelated file. The published container retains the exact archive string and a bound inert receipt. No conventional authority filename, historical process lock or runnable workspace is installed. Vault-open attempts against this target fail. Activation remains a separate root-only operation.

The encrypted reservation commit uses its own Vault writer admission after the filesystem admission exits. Guarded artifact writes must never nest inside another writer guard: a real Engine/backend lease may not be reentrant. Root must supply complete admission for every configured external/backend consumer or refuse the operation; this local profile does not self-certify live sync, PostgreSQL, keychain, scheduler, or native-consumer readiness from an assertion. The Vault authority snapshot and target process exclusion remain held across both phases.

After publication, source/current-owner checks, target physical generation, exact encrypted reservation, single container entry, container hash, archive pin and receipt are rechecked. Rollback reacquires authority/target exclusion, compares the exact creation/archive digest and still-inert target, durably revokes the reservation, removes only its verified container and reads back emptiness. The empty reserved directory and encrypted tombstone remain single-use. Failure before publication removes the exact allocated empty directory and revokes its reservation. Unresolved or changed custody fails closed with a cleanup-required error; root must inspect it before admission.

Focused tests use synthetic newly allocated fixtures beneath `realpath(tmpdir())`; on Windows the canonical path must be on `C:` before creation. Cleanup verifies the exact canonical fixture prefix and parent. The focused test file exercises original envelope bytes, all private control statuses, process restart, prior backup controls, owner/source mutations, explicit budgets, unknown namespaces, hard links, independent ciphertext measurements, no-overwrite target refusal, exact rollback and six completed-write/lost-acknowledgement positions. It makes no provider, model, GUI, native database, downloader, or paid calls.

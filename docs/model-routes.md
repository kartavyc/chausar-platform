# Model routes and speech

The engine offers official installed Codex first, official Claude Code second, then API-key Responses, compatible Chat Completions, localhost Ollama, and a configured managed allowance. It selects one route and makes one dispatch attempt. It never changes routes after an error. Every external route is **experimental / not live verified** until exercised against that operator's installed version or endpoint. An entry in the route list does not certify installation, account entitlement, provider availability, or model support.

## Privacy and exact receipts

`TrustService` checks the current member role and epoch, branch scope, allowed sources and individual source grants. `nothing` denies model dispatch. `shape` sends field names and a question reduced to a fixed business vocabulary; amounts, customer selectors and arbitrary question text are omitted. `samples` adds at most five visible fact rows; callers select existing fact identifiers and fields, never supply their own unrestricted sample blob. Outside text remains data. Cloud requests that read source data require an owner or cofounder to approve the exact payload digest, endpoint and preview. That approval expires, can be consumed once, and cannot survive permission revocation. Local Ollama remains subject to the send policy.

The encrypted authority holds the exact application payload before dispatch, its SHA-256 digest, destination, member epoch, source lineage, one-attempt status, budget reservation and response digest. HTTP receipts contain the exact provider JSON body. Authorization headers are deliberately absent. Official CLI receipts cover the exact stdin submitted to the executable: `receiptBoundary=application-to-official-cli`, `providerPayloadObserved=false`. The CLI may add its own unpublished system prompt and authentication protocol; Chausar does not claim to observe those words or its internal destination. This is a material boundary on full provider-payload certification for subscription CLI routes.

Revocation is checked immediately before the call and after completion. A revoked result is withheld even though an already-started remote request cannot be recalled. Deletion removes the source and derived local records, leaving hashes and no-resend tombstones. Deleting a source requires a current administrator source grant and access to every affected branch; a source mixing allowed and restricted branches is refused. Retention cleanup removes expired facts and dependent records and requires a current owner with every branch and source grant. Remote providers' independent retention is outside local deletion authority.

## Official CLI configuration

Codex starts in a fresh temporary directory, using `exec`, `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, `--skip-git-repo-check`, read-only sandbox, JSON events and a JSON output schema. Config disables shell, unified execution, apps, multi-agent, hooks, memories, plugins, goals, web search and image viewing. Provider request and stream retry counts are zero. An unsupported installed version fails; there is no permissive fallback.

Claude Code uses print mode, `--restricted`, `--safe-mode`, no built-in tools, denied MCP tools, a strict empty MCP configuration, disabled commands, no browser and no session persistence. It uses one turn and an explicit schema. The subprocess environment disables network and structured-output retries, nonstreaming fallback, nonessential traffic, marketplace auto-install and title generation. Managed administrator policy remains outside application control. Live version qualification must inspect that policy as well as tool denial.

Use native official executables. Windows shell wrappers are intentionally refused. The subprocess inherits only the environment needed to find the official executable and its own login. Chausar never opens, copies, saves, converts or exports subscription token files. A CLI configuration cannot accept an API secret.

## HTTP routes and credentials

`openai-responses` posts tools-disabled JSON to the configured HTTPS Responses endpoint. `openai-compatible` posts one tools-disabled Chat Completions request. `ollama` posts a schema-constrained chat request only to loopback. All redirects are refused. `anthropic-messages` posts one Messages API request to `https://api.anthropic.com/v1/messages` with the instructions as `system`, the input as the single user message, no tools declared and `output_config.format` set to the JSON schema; the key goes in `x-api-key` with `anthropic-version: 2023-06-01`. A `refusal`, `tool_use`, `max_tokens` or `pause_turn` stop fails once without a retry; thinking blocks are ignored and only final text is parsed. `subq-snap` (experimental) posts to SubQ's Decisions API (`https://api.subq.ai/v1/systemone`, model `subq-snap-preview`). Snap answers probability-weighted `choice` questions rather than writing text, so Chausar asks two: which registered calculation answers the question (the operation enum plus `none_fits`), and which period preset it names (option names carry exact dates computed at preview time). Below 0.6 confidence, or on `none_fits`, the plan asks for clarification; branch and customer selectors are never filled; any purpose other than the analytical plan is refused with `SNAP_PURPOSE_UNSUPPORTED`. See [the Decisions API](https://docs.subq.ai/endpoints/decisions-api/). `managed` requires an explicitly configured real HTTPS service and credential; there is no included allowance service bundled in this repository.

`ModelGateway.configureRoute(context, config, secret?)` retains an API key in engine memory only. Alternatively supply `credentialEnv: 'CHAUSAR_PROVIDER_KEY'` or inject a credential broker. Keys never enter workspace snapshots, receipts, route metadata or renderer storage. In-memory keys must be supplied again after restart. The broker may implement an encrypted engine-owned secret service; plugin code must not receive it.

The explicit model identifier comes from the operator. The code does not advertise an invented live model or hardcode account entitlements. Configuration supports integer paise strings for `budgetMinor`, `maxCostMinor`, `inputPerMillionMinor` and `outputPerMillionMinor`. Each dispatch reserves its configured maximum using BigInt. Failed calls keep that conservative reservation, and a non-sensitive cumulative route counter survives deletion/retention of detailed receipts. When HTTP token rates are configured, the reservation must cover a conservative request-byte/output-token bound. Provider-reported token usage produces cost only when both operator-configured rates are present; otherwise `actualCostMinor=null` and the receipt says cost was unavailable. Actual usage above an estimate raises the accounted reservation. These local controls cannot retrospectively cap a provider invoice; set the provider's own spend cap as well.

## Route catalogue, pricing and meters

`modelsx.catalogue` lists every route kind with its protocol, receipt boundary, cost model, status and what the founder must supply. `modelsx.pricing` serves a dated price table (integer micro-dollars per million tokens, each entry with its source and the date it was read) and the owner's FX setting in paise per US dollar (`modelsx.setFx`); without an FX rate every rupee cost reads "not counted". `modelsx.applyPricing` writes the converted paise-per-million rates onto a configured route so the gateway measures actual cost. `modelsx.cost`, `modelsx.meters` and `modelsx.jobCost` give per-request estimates, per-route budget/consumed/remaining meters and the cost of a set of model receipts, all BigInt paise rounded up.

## Analytical output contract

The model chooses an operation from the currently published dictionary and may select an inclusive ISO-date period and already-visible branch/customer identifiers. Without a dictionary, a small seed catalog supports the first-day flow. A present but unpublished dictionary provides no executable catalog. Unknown keys, arbitrary operations, impossible dates, unavailable selectors, tools, SQL, code, URLs and numeric explanations fail validation. Optional schema properties may be null and are normalized away. The model never supplies a calculated amount or executable query. The deterministic calculator produces all figures and their proof separately.

```ts
const preview = await gateway.preview(context, { question, routeId });
const approval = preview.approvalRequired
  ? await gateway.approveOutbound(ownerContext, preview.id)
  : undefined;
const { plan, receipt } = await gateway.execute(context, {
  previewId: preview.id, approvalId: approval?.id,
});
```

## Speech providers

`SpeechService` keeps speech separate from model planning. Its default `browser` provider accepts transcript text only and records that the browser provider may process audio remotely; this is not certified offline recognition. A browser transcript can be accepted directly or through a one-use preview. Chromium's Web Speech recognition sends audio to its own service, so the voice family treats the browser as "may use the network": with Send at `nothing` or `shape`, `voice.*` refuses it with `VOICE_LOCAL_ONLY` unless the trusted host option `browserSpeechOnDevice: true` says recognition happens on this computer (default off). Switching voice on without a provider then picks local whisper when one is configured, or refuses `VOICE_NO_LOCAL_PROVIDER`. Under `samples` the browser is allowed and labelled as may-use-network.

Raw audio is kept only while needed: a preview not yet sent keeps its bytes for ten minutes, a dispatch in flight for `SPEECH_IN_FLIGHT_MS` (five minutes, longer than its two two-minute requests). A dispatch older than that was cut off by a crash or restart: it becomes `failed` (`SPEECH_INTERRUPTED`) with its reservation kept. Every other preview or receipt loses its audio at once, digest kept. This sweep runs on every voice call, on the module tick, and on a speech service's first use, which also strips audio that earlier versions left on completed receipts. On first use the process also removes local whisper folders (`chausar-speech-*` in the temp folder) older than an hour.

`local-command` supports an installed `whisper.cpp` `whisper-cli` executable and model, each supplied as an absolute path. It handles wav, mp3 and ogg recordings in a temporary directory, suppresses timestamps and logs, disables decoding fallback and detects language. Chausar makes no network call for this path; the operator must qualify the installed binary. See the [upstream CLI reference](https://github.com/ggml-org/whisper.cpp/blob/master/examples/cli/README.md).

`api-upload` takes an explicit HTTPS transcription endpoint, API key, model and paise-per-minute estimate. It requires the samples policy and a human approval of exact multipart bytes. The preview includes the payload base64 and digest, filename/content type, duration and reservation. Supported uploads are wav, mp3, mp4, webm and ogg, under nine megabytes and five minutes. This adapter performs recorded-file transcription, not a deployed live-voice session. Browser and provider durations/costs are not fabricated as measured billing. See the [OpenAI transcription contract](https://platform.openai.com/docs/api-reference/audio/createTranscription).

Speech provider configurations persist in the encrypted workspace, under the models-ext namespace at `extensions['models-ext'].speech.providers`: kind, label, endpoint, command and model, language, pipeline and service ids, rate and budget in paise, the `CHAUSAR_*` credential variable name, enabled, and a revision. The built-in `browser` provider is always listed; revoking or reconfiguring it stores its own record. A lock and reopen, or a new engine on the same folder, lists the same providers at the same revisions. Keys never enter the workspace: they stay in memory (cleared on lock), come from the credential broker, or come from the named `CHAUSAR_*` variable. After a restart a cloud provider lists `credentialConfigured: false` until its key is given again with `speech.configure` or the broker has it. A preview and approval may still be made, but `speech.transcribe` refuses with `CREDENTIAL_REQUIRED` before anything is sent. Every configure moves the revision on, so a preview made before a reconfigure is refused with `SPEECH_REVOKED`, also after a restart. A configure that changes the kind or endpoint without a new key forgets the key held in memory. `modelsx.speechRevoke` (admin, `{ providerId }` → `{ providerId, enabled: false, revision }`) disables a provider durably and drops its key; configuring it again re-enables it at a new revision. Configuration and revocation are audited (`speech.provider.configured`, `speech.provider.revoked`). The rupee budget is spent from the reservations on durable speech receipts, so a restart does not refill it. Permission changes, provider revocation, redirects and provider errors stop the request without retries.

Purge: speech previews and receipts are removed by the core purge when their sources go. The speech namespace holds nothing derived from a source except confirmations, which name a receipt; a confirmation is removed when its receipt is removed or already gone. Provider settings and bench scores are not source-derived.

### Sarvam, Bhashini and paid live voice (experimental)

These kinds go through the same `speech.configure`, `speech.preview`, `speech.approve` and `speech.transcribe` methods and keep every `api-upload` rule: the samples policy, an exact-bytes preview with its digest, an owner or co-founder approval in the app, one attempt, refused redirects, a paise reservation from the per-minute rate, the rupee budget, credentials only in memory, from the broker or from a `CHAUSAR_*` variable, and revocation checks before and after the call. Wire formats live in `platform/runtime/speech-providers.ts`. None of them has been run against the live service; the tests replay documented reply shapes.

- `sarvam-stt` ([Sarvam speech to text](https://docs.sarvam.ai/api-reference-docs/speech-to-text/transcribe)) posts multipart `file`, `model` (`saaras:v4` or `saaras:v3`) and `language_code` (`hi-IN`, `en-IN`, … or `unknown`) to `https://api.sarvam.ai/speech-to-text` with the `api-subscription-key` header, and reads `transcript` and `language_code`. The REST endpoint is for recordings under 30 seconds, so longer previews are refused. `ratePerMinuteMinor` is required.
- `bhashini-asr` ([config call](https://bhashini.gitbook.io/bhashini-apis/pipeline-config-call), [config request](https://bhashini.gitbook.io/bhashini-apis/pipeline-config-call/request-payload), [config response](https://bhashini.gitbook.io/bhashini-apis/pipeline-config-call/response-payload), [compute request](https://bhashini.gitbook.io/bhashini-apis/pipeline-compute-call/request-payload), [compute response](https://bhashini.gitbook.io/bhashini-apis/pipeline-compute-call/response-payload)) needs a `language` (ISO-639), a `pipelineId`, the `serviceId` and the secret `userID:ulcaApiKey`. The preview shows both steps: the config payload (language and pipeline, no audio) for `getModelsPipeline`, and the exact compute JSON (with base64 wav audio and the sample rate read from the wav header) for the compute endpoint (default `https://dhruva-api.bhashini.gov.in/services/inference/pipeline`). After approval the config call runs first. If its `callbackUrl` differs from the previewed endpoint the request stops with `BHASHINI_CALLBACK_MISMATCH`; if it does not offer the configured service, with `BHASHINI_SERVICE_MISMATCH`; nothing is sent. The returned inference key is used for that one compute call and never stored.
- `live-voice` ([client secrets](https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets/methods/create), [WebRTC guide](https://developers.openai.com/api/docs/guides/realtime-webrtc)) runs only through `voice.start {live:true}`, never through `speech.transcribe`. It previews a minute cap (default 5 minutes, at most 30) and its cost, then, after the owner's approval, posts a transcription-only session request (`{ expires_after: { anchor: 'created_at', seconds: 60 }, session: { type: 'transcription', audio: { input: { transcription: { model } } } } }`) to `https://api.openai.com/v1/realtime/client_secrets`, so the provider only turns speech into text and never answers. The ephemeral secret is in that one reply, never in state. The renderer client `app/ui/src/screens/voice/live-client.ts` connects over WebRTC and hangs up itself at the cap; live voice is refused (`LIVE_VOICE_CAP_NOT_ENFORCED`) unless the trusted host option `liveVoiceClient: true` says that client is in use, which the installed desktop app's engine (an Electron worker) sets. Only one live session per person can be awaiting approval, opening or running (`VOICE_LIVE_BUSY`), checked and recorded in one update. The budget counts the approved cap: the receipt's `costReservedMinor` stays the cap's cost even when the session is stopped early, because the call may go on after a stop. The minutes used (`liveMinutesMs`, `liveChargedMinor`, for `voice.usage` and the meters only) are measured on a monotonic clock held in engine memory per session, so moving the system clock neither erases nor adds minutes; the engine closes the session at the cap on that clock whether or not a stop arrives. After an engine restart that origin is gone and the wall clock is used, never below zero and never below one session-secret lifetime (one minute, or the cap if shorter). Minutes are not from the provider's bill. Any other endpoint is refused with `LIVE_VOICE_NOT_VERIFIED`.

Voice minutes and costs are bucketed by calendar month in the workspace's time zone with the same function as model spend (`platform/runtime/models-ext/months.ts`); an unknown zone falls back to India time.

`voice.speak` reads only a calculator receipt's figures: it says "out of date" first when the receipt or an answer built on it is stale, names each figure with a fixed spoken label for its key (a single total by its operation, else "Total"; never the figure's own label text), and says each amount in the figure's declared unit (rupees, or basis points). An amount in another currency is not read aloud.

### What it understood

`platform/runtime/speech-understood.ts` reads a transcript without a model: Devanagari, romanised Hindi and English. It marks negations (`nahi`, `nahin`, `नहीं`, `mat`, `मत`, `na`, `not`, `don't`, `never` …) as "this flips the meaning", exclusions (`bina`, `बिना`, `without`, `except`), and converts Indian number words (`do lakh` → 2,00,000, `dhai hazaar` → 2,500, `dedh lakh` → 1,50,000, `sava`, `saadhe`, `paune`, `sau`, `hazaar`, `lakh`, `crore`, digits with any grouping) to exact integer strings with Indian grouping and, next to a rupee word, paise. Words that might not be numbers (`do` as "do"/"give", `saath` as "with", `ek` as "a") are flagged rather than guessed, a `lakh` with no count is not read, and unclear parts stay words. `modelsx.speechInterpret` returns this reading and its digest; `modelsx.speechConfirm` records that the person confirmed that exact digest. `modelsx.speechCatalogue` lists every kind with its privacy gate, network, cost model and status, and `modelsx.speechBench` replays recorded clips (`platform/benchmarks/speech/recorded-clips.json`, supplied by the host as `speechBench`) through each provider offline and scores both traps.

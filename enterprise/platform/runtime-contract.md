# Connected investigation runtime

11 September 2026. Implementation binding for the connected local platform. Uses pinned Temporal TypeScript 1.13.2 supplied by the platform dependency owner. This document describes implemented code; the root integration evaluator supplies execution evidence.

Run `node src/runtime-worker.ts` using Node 24 with native TypeScript stripping and a module package. Temporal bundles the workflow separately through its own supported workflow loader. No research modules are imported by production source.

Required environment: `CHAUSAR_CORE_URL` and `CHAUSAR_INTERNAL_SERVICE_TOKEN`. Optional: `TEMPORAL_ADDRESS` (127.0.0.1:7233), `TEMPORAL_NAMESPACE` (default), `TEMPORAL_TASK_QUEUE` (chausar-investigations). Credentials remain in the activity process closure and HTTP header, never workflow arguments. Startup and uncaught failures emit generic messages only. Internal service authentication identifies the worker; the core must additionally resolve current investigation authority on every request.

Workflow type `investigate` accepts only `{investigationId}`. Its stable execution operation identity is `${workflowInfo().workflowId}/execute`. Activity requests POST `/internal/investigations/{id}/execute` with bearer service authentication and `{operationId}`. A 200 completed result is projected to `{status, resultId, revision}`; other response fields are discarded before history. A valid 409 owner_missing becomes a durable wait for signal `ownerAssigned`. Signal versions are captured before dispatch, so assignment between request start and wait registration cannot be lost. The signal is a wakeup, never proof of authority: the next activity calls the authoritative core again using the same operation identity.

A 403 authority_denied is nonretryable and produces terminal `{status:'blocked',code:'authority_denied'}`. Transport errors, 429 and 5xx have at most three attempts, 60-second per-attempt timeout and three-minute overall activity schedule deadline. HTTP requests time out at 45 seconds and do not follow redirects. Other unexpected status/payload combinations are nonretryable protocol errors. Exhausted application activity failures produce a terminal failed outcome. Cancellation and unexpected workflow errors are rethrown to preserve Temporal semantics.

Query `state` returns phase (`executing`, `waiting-owner`, `completed`, `blocked`, `failed`), wait count and owner signal version. There is no transcript or business data in this query. Workflow/operation/investigation/result references are still restricted metadata. The runtime's result is a reference to the core's accepted result, not a second authority over its content.

The worker sends `{type:'ready',component:'runtime-worker'}` through Node IPC after worker creation and entering its run loop. This means the native worker started; it does not certify core HTTP readiness, policy correctness or analytical correctness. SIGINT/SIGTERM trigger graceful worker shutdown. The evaluator may kill the process to exercise durable recovery.

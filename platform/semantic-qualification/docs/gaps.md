# Remaining qualification gaps and parent integration

## Concrete integration contract

The original standalone lane supplied `src/contracts.ts` and `src/index.ts` without changing shared runtime files. Parent subsequently integrated these typed data-only boundaries into `platform/runtime/engine-semantic.ts` and `engine-connectors.ts`. The current source implementation joins synthetic connector publication and consumer readiness; external/native qualification and acceptance remain separate requirements.

Historical alignment against connector commit `af089b75` is retained in `docs/connector-handoff.md`. The current `EngineConnectorService.publish` uses the synchronous `CursorImportService.beforeInsert` hook to call `EngineSemanticService.beforePublish` before inserting facts. Rights, raw read custody, current access/reviewer authority, source controls, golden/holdout evidence and runtime projection are checked; semantic ledgers, separate Engine-owned anchors and connector proofs are retained in the same transaction as publication. Consumer readiness invokes both cursor and semantic `assertReady`, checking current capture/decoder/generation, trusted time, dependencies, retained anchors, exact published facts and requested measure receipts. These mechanisms are implemented for synthetic profiles; they do not qualify external sources or named vendors.

Real-source qualification still needs an original source receipt, raw schema, precise product/version/edition/configuration, complete bounded acquisition, snapshot identity, exact company scope and independent native source totals. The integrated synthetic path verifies retained original page bytes and decoder output, and `semantic-translation.ts` implements opt-in exact translation with separate wire/decoded/compiler fingerprints and bijective row lineage, reexecuted at publication and readiness. The supported runtime projection requires safe integer quantities, no exclusions and no inferred FX. Broader translations and source semantics remain work. Qualified `CanonicalFact` decimal strings remain subject to runtime ontology/projection constraints. A mapping result alone is a proposal: consumers require the relevant qualified operation evidence, current dependencies and source access. The exported mapping helper alone does not perform rights admission.

All company and template/configuration origins are explicit provenance attestations. This package detects overlap in recorded origins; it cannot prove a supplier did not relabel an alternate export or prove that a private family was never seen by a builder. The synthetic split is disclosed, generated before the run and fingerprinted per explicit product pack. A true sealed benchmark needs independent reference stewardship, precommitted hidden origins, authorized coherent books and a separate evaluator.

## Unimplemented or unverified

- Full semantic packs for all 56 groups, product releases, local configurations, export routes, country/jurisdiction profiles and operations. The exact original roster differs from the recovered runtime catalogue's grouping. Catalogue integration remains owned by parent and connector lane.
- Acquisition of real coherent source books and independent controls, sample-specific authorization, external rights retention/revocation, evidence of origins, personal-data minimization and independent business review. There are zero external datasets acquired or admitted here. Current synthetic readiness checks rights/provenance hashes; that does not supply external rights evidence. Generic AdventureWorks/WWI/UCI data is discovery material, not named-system certification.
- Native source profile guards from the source requirements JSON: Razorpay refunded-but-paid orders; Shopify draft generated orders, pre-return/current order totals and successful refund transactions; AIS reported/processed/accepted stages and AIS/26AS overlap; Tally native JSON only in compatible releases; Zoho jurisdiction-specific bundles; PhonePe Pulse channel-specific acquisition/reuse terms. All these native vendor profiles remain unqualified and the executable harness refuses named vendors.
- Separate invoice, delivery, completion, recognition, posting and settlement dates; datetime/timezone boundaries, fiscal calendars, historical corrections/revisions, FX and evidenced rounding, partial settlement fees/netting, recoverable versus nonrecoverable tax, composition/unregistered rules, cross-period refund source evidence, inventory/journal double-entry assertions, opening/closing balances and accrual recognition. Do not reuse the fixture ontology to silently infer those meanings.
- Full ontology-generated deterministic SQL and actual PostgreSQL/DuckDB execution/readback equivalence with source receipts. This lane implements seven fixed BigInt register calculations, and supplies interfaces; no SQL execution or dual-database claim is made.
- A measured learned mapper, company/template/configuration unseen onboarding benchmark, refusal/question-rate policy on an answerable denominator and independently reviewed accepted-wrong business assertions. The current fixture suite's nine required refusals are deliberate attack/ambiguity cases. Proposed GAP ONT-08 thresholds are policy proposals, not real measured onboarding performance.
- Publisher signatures, authenticated upstream controls and secure independent append-only ledger retention. Transactionally retained Engine-owned anchors, persisted local custody and current user/source/reviewer authorization checks are implemented for synthetic profiles. Local hashes and state anchors cannot authenticate caller-supplied controls as vendor-signed or establish secure upstream custody.
- Financial writeback qualification and operation-specific approval/readback evidence. The original standalone lane performed no accounts, payments, live writes, deployment or external training; the synthetic integration does not qualify those effects.
- Historical validation limit: the original standalone environment had no local TypeScript compiler/dependencies, so it used Node source syntax and executable tests. This is not a claim that the current integrated build lacks static checks. Root/native acceptance remains outside this standalone package.

These gaps prevent production or arbitrary-company correctness claims. Synthetic passes establish executable refusal and evidence mechanisms; they do not finish full Chausar ontology semantics or connector onboarding qualification.
